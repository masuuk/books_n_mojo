Guide · AI Agent Engineering

Building AI Agents
Mojo 1.x on the Python ecosystem

A practical reference for calling the OpenAI API and building conversational agents from Mojo 1.x, using its native Python interoperability layer to reach the Python AI ecosystem. Every listing is Mojo; the Python side is what it drives.

📖 What is an AI agent?

At its core, an AI agent (or chatbot) is a system that maintains a conversation history (state) and interacts with a Large Language Model (LLM) like gpt-5-mini. Unlike a simple single-turn API call, an agent remembers previous messages, allowing for coherent, multi-turn dialogues.

This guide builds those agents in Mojo 1.x — an emerging high-performance language positioned as a superset of Python — and reaches Python, the industry standard for AI tooling, through Mojo's interoperability layer. The first sections cover the fundamentals; later sections progress to streaming, tool calling, memory management, structured output, and production-grade error handling.

01 Basic Single-Turn API Call

difficulty · easy no state

The simplest interaction: send one prompt, print one response. No conversation history is maintained.

💡 Mojo context: Python interoperability

Mojo interoperates directly with the Python ecosystem via std.python, so instead of reimplementing the OpenAI SDK, you import and drive the Python package from Mojo — giving you Python's AI ecosystem with Mojo's systems-level performance where you need it.

Mojo 1.x 
# Import the Python interop standard library
from std.python import Python

# Mojo requires an explicit main function with a 'raises' trait for error handling
def main() raises:
    # Import the Python OpenAI package
    var openai = Python.import_module("openai")

    # Create the OpenAI client
    var client = openai.OpenAI()

    # Build the request using Python's list and dict constructors via interop
    var messages = Python.list(
        Python.dict(
            role="user",
            content="Explain what an AI agent is in one sentence."
        )
    )

    # Send the request (calls the Python API directly)
    var response = client.chat.completions.create(
        model="gpt-5-mini",
        messages=messages
    )

    # Print the answer
    print(response.choices[0].message.content)

02 Multi-Turn Conversational Agent

difficulty · moderate stateful chat loop

To build a true "agent" or chatbot, you need a loop that continuously accepts user input, appends it to a growing list of messages (the context window), and sends the entire history to the API on every turn.

Mojo 1.x 
from std.python import Python

def main() raises:
    # Import the Python OpenAI package
    var openai = Python.import_module("openai")

    # Create the OpenAI client with explicit API key
    var client = openai.OpenAI(
        api_key="YOUR_API_KEY"
    )

    # Initialize an empty Python list for conversation history
    var messages = Python.list()

    while True:
        # Read a line from stdin using Mojo's builtin input()
        var user_input = input("You: ")

        # Check for exit commands
        var cleaned = user_input.strip().lower()
        if cleaned == "exit" or cleaned == "quit":
            break

        # Add user message using Python.dict()
        messages.append(
            Python.dict(
                role="user",
                content=user_input
            )
        )

        # Send conversation to OpenAI
        var response = client.chat.completions.create(
            model="gpt-5-mini",
            messages=messages
        )

        # Extract assistant response
        var reply = response.choices[0].message.content

        # Add assistant response to conversation history
        messages.append(
            Python.dict(
                role="assistant",
                content=reply
            )
        )

        # Display response
        print("Bot:", reply)

03 System Prompts & Generation Parameters

difficulty · easy role-aware fine-tune output

A system message steers the model's behaviour for the entire conversation — personality, tone, constraints — separately from each user turn. It is the standard mechanism for "role-playing" personas and for imposing rules the model must follow.

Generation parameters shape every reply: temperature trades determinism for creativity, max_tokens caps the output length (guarding both cost and latency), and top_p is an alternative randomness dial.

🎚️ Choosing parameters

Use a low temperature (0 → 0.3) for factual, consistent output — great for extraction, classification, or code. Raise it (0.7 → 1.2) for brainstorming and creative writing. As a rule of thumb, change temperature or top_p, not both.

Mojo 1.x 
from std.python import Python

def main() raises:
    var openai = Python.import_module("openai")
    var client = openai.OpenAI()

    # The system message shapes behaviour for the whole conversation
    var messages = Python.list(
        Python.dict(
            role="system",
            content="You are a coding mentor. Be brief, use short examples, and never assume the reader has prior knowledge.",
        ),
        Python.dict(role="user", content="What is a closure?"),
    )

    # same generation parameters, passed straight through the interop layer
    var response = client.chat.completions.create(
        model="gpt-5-mini",
        messages=messages,
        temperature=0.7,
        max_tokens=250,
        top_p=0.9,
    )

    print(response.choices[0].message.content)

04 Streaming Responses

difficulty · moderate low latency SSE

Long answers feel slow if the client waits for the entire completion before printing anything. Setting stream=True returns a Server-Sent Events (SSE) iterator that yields text tokens as they are generated — output appears progressively, like in ChatGPT.

In the parameters you learn to inspect here: each chunk carries a delta rather than a full message, so you rebuild the answer by printing deltas as they arrive.

⏱️ When to stream

Stream for anything user-facing. The perceived latency of a 2,000-token answer drops from several seconds to effectively zero. For non-interactive batch pipelines (summarization, extraction jobs) a non-streaming call is simpler and fine.

Mojo 1.x 
from std.python import Python

def main() raises:
    var openai = Python.import_module("openai")
    var client = openai.OpenAI()

    var messages = Python.list(
        Python.dict(role="user", content="Explain why 'cloud' is a misnomer, in exactly 5 sentences."),
    )

    # stream=True returns an SSE iterator instead of a single whole response
    var stream = client.chat.completions.create(
        model="gpt-5-mini",
        messages=messages,
        stream=True,
    )

    # Iterate the Python iterator from Mojo and print deltas as they arrive
    for var chunk in stream:
        var delta = chunk.choices[0].delta.content
        if delta:
            print(delta, end="")   # accumulate on one line, token by token
    print()

05 Tool Calling: From Chatbot to Agent

difficulty · advanced action-oriented the agent primitive

A chatbot only talks. An agent acts — and the standard mechanism is tool calling (function calling). You describe a function to the model; when the model decides the answer requires that function, it returns a request instead of text. Your code executes the function locally and feeds the result back as a special role: "tool" message, then the model composes its final answer using that real data.

💡 Why this is the key step

This loop — model requests → you execute → tool result feeds back → model answers — is the core of every serious agent framework (OpenAI Assistants, LangChain, AutoGen). From here you can chain multiple tools: weather lookup, database queries, file operations, web search. The same pattern works identically in Python and through Mojo's interop layer.

The example below wires a mock weather service so the agent can genuinely answer a question it otherwise could not.

Mojo 1.x 
from std.python import Python

# A tool: a plain Mojo function. Swap the body for a real weather API in production.
def get_weather(city: String) -> String:
    return "Current conditions in " + city + ": 21°C, partly cloudy, 10% chance of rain."

def main() raises:
    var openai = Python.import_module("openai")
    var json = Python.import_module("json")
    var client = openai.OpenAI()

    # 1) Describe the tool so the model knows it exists and how to call it
    var tools = Python.list(
        Python.dict(
            type="function",
            function=Python.dict(
                name="get_weather",
                description="Get the current weather for a city",
                parameters=Python.dict(
                    type="object",
                    properties=Python.dict(
                        city=Python.dict(
                            type="string",
                            description="City name",
                        )
                    ),
                    required=Python.list("city"),
                ),
            ),
        )
    )

    var messages = Python.list(
        Python.dict(
            role="user",
            content="Should I bring an umbrella in Berlin tomorrow?",
        )
    )

    # 2) Ask, letting the model decide when to use the tool ("auto")
    var response = client.chat.completions.create(
        model="gpt-5-mini",
        messages=messages,
        tools=tools,
        tool_choice="auto",
    )

    var message = response.choices[0].message

    if message.tool_calls:
        # 3) The model requested a call — execute it locally...
        for var call in message.tool_calls:
            var args = json.loads(call.function.arguments)
            var result = get_weather(String(py=args["city"]))

            # 4) ...and feed the result back as a "tool" message
            messages.append(
                Python.dict(
                    role="tool",
                    tool_call_id=call.id,
                    content=result,
                )
            )

        # 5) Ask again with the tool result in context for the final answer
        var final = client.chat.completions.create(
            model="gpt-5-mini",
            messages=messages,
            tools=tools,
        )
        print(final.choices[0].message.content)
    else:
        print(message.content)

🔁 Generalize the pattern

The weather function is interchangeable: replace it with a search_docs(), query_db(), send_email(), or any other function. Register multiple tools in the tools list and the model picks. Production agents usually wrap steps 3–5 in a while loop so the model can chain several tool calls before answering.

06 Memory Management & Context Limits

difficulty · advanced cost control scaling state

Every turn resends the entire messages history — so token usage (and cost) grows linearly with conversation length, and eventually you bump into the model's context window. Robust agents manage memory explicitly. The simplest strategy is a sliding window: keep the system prompt, forget the oldest turns once history exceeds a budget.

🧠 Beyond the sliding window

Summarization: when the window fills, ask the model to condense everything so far into a short memory, then replace the old turns with that summary. Selective recall: keep factual answers (preferences, facts learned) and drop chit-chat. External memory: store long-term facts in a vector database and inject relevant snippets on each turn.

Mojo 1.x 
from std.python import Python

# Trim a Python list from the front until it fits under the limit
def trim(history: PythonObject, max_history: Int):
    while len(history) > max_history:
        history.pop(0)

def main() raises:
    var openai = Python.import_module("openai")
    var client = openai.OpenAI()
    var max_history: Int = 10

    var messages = Python.list(
        Python.dict(
            role="system",
            content="You are a pithy assistant. Answer in one or two sentences.",
        )
    )

    while True:
        var user_input = input("You: ")
        var cleaned = user_input.strip().lower()
        if cleaned == "exit" or cleaned == "quit":
            break

        messages.append(Python.dict(role="user", content=user_input))
        trim(messages, max_history)

        var response = client.chat.completions.create(
            model="gpt-5-mini",
            messages=messages,
        )
        var reply = response.choices[0].message.content

        messages.append(Python.dict(role="assistant", content=reply))
        trim(messages, max_history)

        print("Bot:", reply)

07 Structured Output with JSON Mode

difficulty · moderate machine-readable JSON mode

Chat text is fine for humans, but agents need structured data for programmatic control flow — extracting fields, feeding downstream systems, or chaining tools. JSON mode constrains the model to emit valid JSON. Combine it with a system message that describes the schema you expect.

🧾 Note on values

JSON mode guarantees valid JSON syntax, not the schema you asked for. For guaranteed schemas use response_format with a strict tool schema, or validate (jsonschema in Python) and retry on failure. Wrap the parsed result in a try/except — models occasionally hallucinate keys.

Mojo 1.x 
from std.python import Python

def main() raises:
    var openai = Python.import_module("openai")
    var json = Python.import_module("json")
    var client = openai.OpenAI()

    var response = client.chat.completions.create(
        model="gpt-5-mini",
        messages=Python.list(
            Python.dict(role="system", content="You output valid JSON only. No markdown, no prose."),
            Python.dict(role="user", content="List 3 fruits with a color and a price each."),
        ),
        response_format=Python.dict(type="json_object"),   # guarantee valid JSON output
    )

    # Parse via interop and work with the data programmatically
    var data = json.loads(response.choices[0].message.content)

    for var fruit in data["fruits"]:
        print(String(py=fruit["name"]) + " — " + String(py=fruit["color"]) + " — $" + String(py=fruit["price"]))

08 Error Handling, Retries & Backoff

difficulty · advanced production-ready resilience

Networks fail, and LLM providers throttle bursts. A production agent treats API errors as a fact of life: rate limits deserve exponential backoff so you don't hammer the endpoint; transient connection errors deserve plain retries; hard failures (auth, malformed request) should propagate immediately.

💡 Mojo error interop

Mojo's def main() raises propagates any Python exception surfaced from the interop call as a Mojo error. Because Mojo cannot easily distinguish specific Python exception types through interop, the Mojo example catches broadly with a bare except: — catch the typed error on the Python side of the bridge when you need that granularity.

Mojo 1.x 
from std.python import Python

# Mojo has no mutable global scope, so import modules and build the
# client inside main() and pass them into the helper as arguments.

def get_reply(
    client: PythonObject,
    time: PythonObject,
    messages: PythonObject,
    max_retries: Int = 3,
) raises -> String:
    # Safe send with retry for flaky networks / rate limits
    var attempt: Int = 0
    while attempt < max_retries:
        try:
            var response = client.chat.completions.create(
                model="gpt-5-mini",
                messages=messages,
            )
            return String(py=response.choices[0].message.content)
        except:
            # Bare except: interop surfaces Python exceptions as Mojo errors.
            # Exponential backoff: 1s, 2s, 4s
            var wait: Float64 = 2.0 ** Float64(attempt)
            print("Error — retrying in " + str(wait) + "s")
            time.sleep(wait)
            attempt += 1
    raise Error("Exceeded max retries")

def main() raises:
    var openai = Python.import_module("openai")
    var time = Python.import_module("time")
    var client = openai.OpenAI()

    var messages = Python.list(
        Python.dict(role="user", content="Why is the sky blue?")
    )
    print(get_reply(client, time, messages))

♻️ Or skip the boilerplate

The OpenAI Python SDK ships with a max_retries client option that wraps calls in sensible retry logic with backoff automatically: client = OpenAI(max_retries=3). The manual loops above still matter — they show you how to add domain behaviour (logging, fallbacks, circuit breakers) on top.

10 Security & Best Practices

"YOUR_API_KEY" appears in the examples above purely for clarity. In production, never hardcode credentials directly in source.

  • Python: omit the api_key argument — the client automatically reads OPENAI_API_KEY from the environment.
  • Mojo: fetch environment variables via interop: var os = Python.import_module("os") then os.getenv("OPENAI_API_KEY").

Every turn resends the full messages history, so token usage — and cost — grows with conversation length. For long-running agents, trim or summarize older turns before they're re-sent (section 06), or track a running token count and prune once you approach the model's context limit.

Tool calling makes your agent genuinely powerful — and genuinely dangerous. Treat model-provided arguments as untrusted input: validate them before executing, whitelist allowed operations, and never expose destructive or privileged tools (shell execution, deletions, admin actions) to the model without human approval.

Mojo's def main() raises signature means any exception surfaced from the underlying Python call (network failure, rate limits, malformed responses) propagates as a Mojo error. Wrap API calls in try/except blocks where the agent needs to keep running rather than terminate on a single failed request (section 08).

Never parse free-form prose to drive control flow. Use JSON mode or tool schemas (section 07) so the model returns typed, validated data. This also removes most prompt-injection surface area that comes from interpreting natural-language instructions as commands.
