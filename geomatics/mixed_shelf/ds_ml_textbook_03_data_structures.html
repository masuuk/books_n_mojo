🧮 Data Structures & Operations

Arrays, tensors, and vectorized computations — the building blocks of high-performance numerical programming in Mojo.

Arrays and Lists

Mojo provides two core sequential containers: List and Array. They serve different purposes and have distinct performance characteristics.

The List Type

List is a dynamically-sized, heap-allocated collection — similar to Python's list. It can grow and shrink at runtime, making it ideal for situations where the number of elements isn't known ahead of time.

The Array Type

Array is a fixed-size, stack-allocated collection. Because the compiler knows the size at compile time, it can place the data directly on the stack — no heap allocation, no pointer chasing. This makes Array significantly faster for small, known-size collections.

Python has only one of these: a single dynamically-sized list. A Python tuple is the nearest equivalent to a fixed-size Array, but it is a layout of pointers to boxed objects, not a contiguous run of unboxed Float64 — which is exactly the difference Mojo's stack-allocated Array[Float64, 3] makes. In NumPy the same contrast appears as np.zeros((3,), dtype=np.float32) against a list of Python floats.

from collections import List

def array_demo():
    # Dynamic list — can grow and shrink
    var scores = List[Float64]()
    scores.append(9.5)
    scores.append(8.7)
    scores.append(7.2)
    print("Scores:", scores)
    print("Length:", len(scores))

    # Fixed-size array — stack allocated
    var coordinates = Array[Float64, 3](
        1.0, 2.0, 3.0
    )
    print("x =", coordinates[0])
    print("y =", coordinates[1])

    # Iterate over a list
    for s in scores:
        print(s * 10.0)
🚀 Pro Tip:

Use Array when you know the size at compile time — it avoids heap allocation entirely. Use List when the size is dynamic. In hot loops over numerical data, Array can be significantly faster due to cache locality.

Tensors

Tensors are the fundamental data structure for machine learning and scientific computing. Mojo's Tensor type is a multidimensional array designed for high-performance numerical work. Unlike a list-of-lists, a tensor stores data in a contiguous block of memory, enabling efficient vectorized operations.

The Tensor type is parameterized by its element type (e.g., Float32, Float64, Int32) and supports arbitrary dimensions. Creating a tensor is straightforward — specify the shape as a tuple of integers.

from math import sqrt

def tensor_basics():
    # Create a 2x3 tensor of zeros
    var t = Tensor[Float32](2, 3)
    print("Shape:", t.shape())

    # Create a tensor with specific values
    var mat = Tensor[Float32](2, 2)
    mat[0, 0] = 1.0
    mat[0, 1] = 2.0
    mat[1, 0] = 3.0
    mat[1, 1] = 4.0

    # Element access
    print("mat[0,1] =", mat[0, 1])

    # Fill with a constant
    var ones = Tensor[Float32](3, 3)
    ones.fill(1.0)
💡 Key Insight:

Mojo tensors are stored in row-major (C-style) order by default, just like NumPy arrays. The contiguous memory layout means that iterating over elements in row-major order is cache-friendly and maximizes memory bandwidth.

The NumPy spellings map across one-for-one, with the dtype becoming the parameter: np.zeros((2, 3), dtype=np.float32) is Tensor[Float32](2, 3), and the fill helper np.ones((3, 3), dtype=np.float32) is Tensor[Float32](3, 3) followed by .fill(1.0). Where NumPy infers the shape from a nested list, Mojo wants the dimensions stated up front and the values assigned by index — which is what lets the compiler size the allocation before the program runs.

Vectorized Computations

Vectorized operations apply a function to an entire array at once, without explicit Python-style for loops. In Mojo, these operations compile to SIMD (Single Instruction, Multiple Data) instructions that process multiple elements per CPU cycle.

When you write element-wise operations on tensors, the Mojo compiler automatically vectorizes them using SIMD. This means a loop that adds two arrays of 1 million elements can execute 4–16 elements at a time (depending on your CPU's SIMD width), giving you near-linear speedups.

The initialization loop above is where NumPy would reach for np.arange(n, dtype=np.float32). Writing the loop out is the point: it is the one part of the kernel Mojo will not fold away, and it is still compiled to straight-line SIMD. Everything after it — the additions, the multiplies, the scalar broadcast — is a single overloaded operator that the compiler lowers for you.

from tensor import Tensor

def vectorized_demo():
    var n = 1000

    # Create two tensors
    var a = Tensor[Float32](n)
    var b = Tensor[Float32](n)
    var result = Tensor[Float32](n)

    # Initialize
    for i in range(n):
        a[i] = Float32(i)
        b[i] = Float32(i) * 2.0

    # Element-wise addition — auto-vectorized
    result = a + b

    # Element-wise multiplication
    result = a * b

    # Scalar operations broadcast automatically
    result = a * 3.14 + 1.0

    print("result[0] =", result[0])
    print("result[999] =", result[999])

Broadcasting and Matrix Multiplication

Broadcasting lets you apply operations between tensors of different shapes. When you add a scalar to a tensor, or add a 1-D vector to a 2-D matrix, Mojo automatically expands the smaller shape to match — without copying data.

Matrix multiplication is the workhorse of linear algebra and deep learning. Mojo provides the matmul function for this, which dispatches to optimized BLAS routines under the hood.

from tensor import Tensor
from math import sqrt

def linear_algebra_demo():
    # Broadcasting: scalar + tensor
    var t = Tensor[Float32](3, 3)
    t.fill(2.0)
    t += 1.0           # each element becomes 3.0

    # Broadcasting: row vector + matrix
    var row = Tensor[Float32](3)
    row[0] = 1.0; row[1] = 2.0; row[2] = 3.0

    # Matrix multiplication
    var a = Tensor[Float32](2, 3)
    a[0,0] = 1.0; a[0,1] = 2.0; a[0,2] = 3.0
    a[1,0] = 4.0; a[1,1] = 5.0; a[1,2] = 6.0

    var b = Tensor[Float32](3, 2)
    b[0,0] = 7.0;  b[0,1] = 8.0
    b[1,0] = 9.0;  b[1,1] = 10.0
    b[2,0] = 11.0; b[2,1] = 12.0

    var c = matmul(a, b)  # Result is 2x2
    print("c[0,0] =", c[0, 0])  # 58.0
    print("c[1,1] =", c[1, 1])  # 154.0
⚠️ Important:

Broadcasting rules in Mojo follow NumPy's conventions: dimensions are aligned from the right, and a dimension of size 1 is stretched to match. However, Mojo enforces type consistency — you cannot broadcast between Float32 and Int32 without explicit conversion.

Matrix multiplication has two spellings on either side of the interop line. In NumPy it is the @ operator, c = a @ b, with np.matmul(a, b) as the spelled-out form; in Mojo it is the matmul function, c = matmul(a, b), which dispatches to the same optimized BLAS routines. Both return the same 2×2 result above, and both spell the constant-fill differently: np.full((3, 3), 2.0, dtype=np.float32) against Tensor[Float32](3, 3) plus .fill(2.0).
