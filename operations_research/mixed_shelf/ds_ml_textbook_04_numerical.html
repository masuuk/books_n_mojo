🔢 Numerical Computing

Linear algebra, statistics, random numbers, and performance benchmarks in Mojo.

Linear Algebra with BLAS/LAPACK

Linear algebra is the backbone of machine learning, graphics, and scientific simulation. Mojo provides direct access to BLAS (Basic Linear Algebra Subprograms) and LAPACK (Linear Algebra PACKage) — the same optimized routines that power NumPy, MATLAB, and TensorFlow.

The key difference is that in Mojo, you call these routines directly without crossing a language boundary. In Python, NumPy wraps BLAS through C extensions; in Mojo, the compiler inlines and optimizes these calls as part of your own code.

Common Operations

  • Dot product: dot(a, b) — inner product of two vectors
  • Matrix-vector multiply: matmul(A, x) — foundation of neural network forward passes
  • Matrix-matrix multiply: matmul(A, B) — the most compute-intensive operation in deep learning
  • Transpose: A.T — returns a transposed view without copying data
from tensor import Tensor
from math import sqrt

def linalg_demo():
    # Dot product
    var a = Tensor[Float32](4)
    var b = Tensor[Float32](4)
    for i in range(4):
        a[i] = Float32(i + 1)
        b[i] = Float32(i + 1) * 2.0
    var dp = dot(a, b)  # 60
    print("Dot product:", dp)

    # Matrix-vector multiply
    var M = Tensor[Float32](3, 3)
    M[0,0]=1.0; M[0,1]=2.0; M[0,2]=3.0
    M[1,0]=4.0; M[1,1]=5.0; M[1,2]=6.0
    M[2,0]=7.0; M[2,1]=8.0; M[2,2]=9.0

    var v = Tensor[Float32](3)
    v[0]=1.0; v[1]=0.0; v[2]=-1.0

    var result = matmul(M, v)
    print("M * v =", result[0], result[1], result[2])

    # Frobenius norm
    var norm: Float32 = 0.0
    for i in range(3):
        for j in range(3):
            norm += M[i, j] * M[i, j]
    norm = sqrt(norm)
    print("Frobenius norm:", norm)
💡 Key Insight:

Mojo's matmul dispatches to the best available implementation at compile time — MKL on Intel, cuBLAS on NVIDIA GPUs, or an optimized pure-Mojo fallback. You get hardware-optimal performance without platform-specific code.

Each NumPy spelling has a Mojo counterpart, usually just a different name: np.dot(a, b) is dot(a, b), the @ operator M @ v is matmul(M, v), and A.T is A.T as well — a transposed view, not a copy. The one that deliberately looks different is the norm: np.linalg.norm(M) is a single call into LAPACK, while the Mojo pane above writes the Frobenius norm out as the double loop that defines it, because writing the loop is what lets the compiler keep the accumulation in a register.

Descriptive Statistics

Computing summary statistics — mean, variance, standard deviation, min, max — is a daily task in data science. Mojo makes these operations fast and explicit. Unlike Python's NumPy, where np.mean() hides a chain of C calls and type checks, Mojo's statistical functions compile directly to machine code.

from math import sqrt

def mean(data: List[Float64]) -> Float64:
    var total: Float64 = 0.0
    for x in data:
        total += x
    return total / Float64(len(data))

def std_dev(data: List[Float64]) -> Float64:
    var mu = mean(data)
    var sq_sum: Float64 = 0.0
    for x in data:
        sq_sum += (x - mu) * (x - mu)
    return sqrt(sq_sum / Float64(len(data)))

def main():
    var data = [2.1, 4.5, 3.3, 7.8, 1.2, 6.4, 5.9]
    print("Mean:", mean(data))
    print("Std Dev:", std_dev(data))
💡 Key Insight:

In NumPy the same numbers are four one-liners — np.mean(data), np.std(data), np.min(data), np.max(data) — and the two functions above are what they are computing underneath. Dividing by Float64(len(data)) is what makes this the population standard deviation, the same default np.std uses; pass n - 1 instead for the sample deviation. Min and max need no library at all: they are a single comparison per element in a for loop over the list.

Random Number Generation

Random number generation is essential for machine learning — initializing weights, data augmentation, Monte Carlo simulations, and stochastic gradient descent. Mojo provides a high-performance random module. Unlike Python's random module (single-threaded), Mojo's RNG is designed for parallelism with independent streams per thread.

There is one seed, not two. A NumPy script that wants reproducibility has to seed the standard library and NumPy separately, random.seed(42) alongside np.random.seed(42), because they are two unrelated generators. The Mojo pane calls seed(42) once and every later draw — random_float64() for the unit interval, random_uniform(5.0, 10.0) for a scaled range, random_normal() for the standard normal — comes from that one seeded stream. The random_float64 name is also the honest one: the return type is part of the function, where random.random() hides it.

from random import random_float64, random_uniform, random_normal, seed

def rng_demo():
    seed(42)

    var r1 = random_float64()         # [0, 1)
    var r2 = random_uniform(5.0, 10.0) # [5, 10)
    var r3 = random_normal()           # N(0, 1)

    print("Uniform:", r1)
    print("Range:", r2)
    print("Normal:", r3)

    # Generate random weight vector
    var weights = List[Float64]()
    for _ in range(5):
        weights.append(random_normal())
    print("Weights:", weights)

Performance Benchmarks

Mojo compiles to native machine code with SIMD vectorization. Operations that are slow in pure Python run at near-C speeds. Here's a comparison for computing the sum of squared differences between two vectors of length 1 million:

LanguageImplementationTime
Pythonfor-loop~800 ms
PythonNumPy vectorized~3 ms
MojoCompiled + SIMD~0.5 ms
from time import now
from random import random_float64

def sse_benchmark(n: Int) -> Float64:
    var a = Tensor[Float64](n)
    var b = Tensor[Float64](n)
    for i in range(n):
        a[i] = random_float64()
        b[i] = random_float64()

    var start = now()
    var sse: Float64 = 0.0
    for i in range(n):
        var diff = a[i] - b[i]
        sse += diff * diff
    var elapsed = now() - start
    print("Time:", elapsed, "ns")
    return sse

def main():
    sse_benchmark(1_000_000)
🚀 Pro Tip:

The benchmark shows Mojo reaching near-native performance for raw loop work — roughly 1600x faster than a Python for-loop. Mojo achieves this while maintaining Python-like syntax, making it much more accessible for data scientists.

The now() clock and the # 1_000_000 size make the two harnesses directly comparable. The NumPy version reaches for np.random.rand(n) to fill the vectors, brackets the timed region with time.perf_counter(), and expresses the whole computation as one expression, np.sum((a - b) ** 2) — hence its ~3 ms row in the table above, against ~800 ms for an explicit Python loop and ~0.5 ms for the compiled Mojo loop that walks the same two arrays. The Mojo pane is deliberately the slowest-looking of the three: a plain for loop, which is the thing being measured.
