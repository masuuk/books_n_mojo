🚀 Getting Started with Mojo

Install the SDK, learn the core syntax, and write your first Mojo program.

Installation

Mojo is distributed as part of the Mojo SDK, which includes the compiler, debugger, and standard library. The recommended way to install it is through curl on macOS and Linux. Since Mojo 1.x, the entire language is also open source under Apache 2.0 (with LLVM exceptions), so you can build the compiler and standard library yourself from github.com/modular/modular.

# Install the Mojo SDK
curl -fsSL https://get.modular.com/install | bash

# Verify installation
mojo --version

# Create and run your first file
echo 'print("Hello, Mojo!")' > hello.mojo
mojo hello.mojo
# Pull the official Mojo Docker image
docker pull ghcr.io/modular/mojo:latest

# Run an interactive Mojo shell
docker run -it -v $(pwd):/workspace ghcr.io/modular/mojo:latest

# Inside the container, run a file
mojo hello.mojo
# Mojo is open source (Apache 2.0, with LLVM exceptions)
# Clone the repository and build with Bazel
git clone https://github.com/modular/modular.git
cd modular

# Build the compiler + stdlib from source and run a file
./bazelw run --config=build-mojo KGEN:mojo -- run hello.mojo

# Or use a prebuilt nightly compiler instead of building from scratch
./bazelw run --config=prebuilt-mojo KGEN:mojo -- run hello.mojo

The Mojo REPL is also available — just run mojo with no arguments to enter an interactive session where you can experiment with expressions line by line, similar to Python's REPL.

🚀 Pro Tip:

If you have Python installed, you can use mojo run hello.mojo as an alias for mojo hello.mojo. Both work identically.

Basic Syntax: one keyword, def

Mojo 1.x defines all functions with a single keyword: def. How strict your function is depends on whether you annotate it. Understanding this is critical to writing idiomatic Mojo.

An unannotated def

An unannotated def behaves almost exactly like a Python function. Parameters are dynamically typed, and you get the full flexibility (and looseness) of Python semantics. This makes it easy to port Python code to Mojo without changing every line.

An annotated def

Type annotations turn the same def strict: annotated parameters are checked at compile time, arguments are immutable by default, and the compiler can perform full static analysis. This is where you get C-level performance.

# unannotated def — Python-like, dynamically typed
def add_loose(a, b):
    return a + b

# annotated def — strict, fully typed, high-performance
def add_strict(a: Int64, b: Int64) -> Int64:
    return a + b

# annotated arguments are immutable by default
def greet(name: String) -> String:
    return "Hello, " + name

# mut marks a mutable parameter
def increment(mut x: Int64):
    x += 1
⚠️ Important:

Prefer fully-annotated def functions by default. Leave annotations off only when porting Python code or writing quick scripts. Type annotations unlock compile-time checks and optimizations that untyped code cannot provide.

Notice the mut keyword (renamed from the pre-1.0 inout) — this is how Mojo marks a parameter as mutable. By default, function arguments are immutable, which prevents accidental side effects.

💡 Coming from Python:

Three spellings change when you port. Type hints are optional in Python but enforced in Mojo, so def greet(name: str) -> str: becomes def greet(name: String) -> String: with the str spellings capitalized. Python's integers are immutable and simply rebound by name, so it has no mut at all — in Mojo a parameter that is rebound has to be declared mut or the call is an error. And formatted output moves from an f-string, f"Hello, {name}", to a t-string, t"Hello, {name}", or to separate print arguments.

Variables: var

Mojo 1.x declares all local variables with a single keyword:

  • var — declares a variable. The keyword is mandatory: assigning to a new name without var is a deprecation error.

Unlike Python — where variables spring into existence on first assignment — Mojo makes the declaration explicit so the compiler always knows when a name enters scope. A variable you never reassign is your immutable binding.

def main():
    var x = 10         # constant by convention — never reassign
    var y = 20         # mutable — can reassign
    y = 30             # OK

    # Type annotations are optional with inference
    var name: String = "Mojo"
    var pi: Float64 = 3.14159
    var count: Int = 42

    # Printing values
    print("x =", x, "y =", y)
💡 Key Insight:

Mojo performs type inference when you don't specify a type — the compiler deduces the type from the right-hand side. This keeps code concise while maintaining full static typing under the hood.

In Python the annotation is purely advisory and the name is just a label on a mutable cell, so x = 10 can be rebound freely. In Mojo the declaration is the contract, and "a variable you never reassign" is the safe default. If you need a genuinely fixed, hashable value in Python, the usual stand-in is a tuple — a tuple cannot be rebound but its contents still can. Mojo has no need for that workaround: the absence of reassignment is already what var expresses.

Control Flow

Mojo's control flow looks familiar to Python developers: if, for, and while work as you'd expect, with a few key differences.

Conditional Expressions

if / elif / else work just like Python. Parentheses are optional. The condition must evaluate to Bool.

Loops

for loops iterate over ranges or collections using in. The range() function generates integer sequences. while loops work identically to Python.

def control_flow_examples():
    # if / elif / else
    var score = 85
    if score >= 90:
        print("Excellent")
    elif score >= 70:
        print("Good")
    else:
        print("Needs improvement")

    # for loop with range
    for i in range(5):
        print(i)

    # for loop over a list
    var fruits = ["apple", "banana", "cherry"]
    for fruit in fruits:
        print(fruit)

    # while loop
    var n = 5
    while n > 0:
        print(n)
        n -= 1

Like Python, Mojo uses indentation — not curly braces — to delimit blocks. Where Python opens a block with a colon and indents, Mojo does exactly the same: there are no { } in sight. The if / elif / else chain and the for / in / range() loop above are the whole story: the syntax a Python reader expects is the syntax Mojo uses, and while behaves identically too.

🚀 Pro Tip:

Mojo's for loops compile to efficient machine code with no iterator overhead. Unlike Python, there is no per-iteration type checking or boxing — the compiler unrolls and vectorizes loops when possible.

Your First Mojo Program

Let's put it all together. Here's a complete Mojo program that declares variables, uses control flow, and defines both strict annotated and lenient unannotated def functions.

def classify_temperature(temp: Float64) -> String:
    if temp < 0.0:
        return "Freezing"
    elif temp < 20.0:
        return "Cold"
    elif temp < 35.0:
        return "Warm"
    else:
        return "Hot"

def main():
    var readings = [-5.0, 12.5, 22.0, 38.5, 8.0]

    var hot_count = 0
    var total: Float64 = 0.0

    for temp in readings:
        var category = classify_temperature(temp)
        print(temp, "°C →", category)
        if category == "Hot":
            hot_count += 1
        total += temp

    var avg = total / Float64(len(readings))
    print("\nAverage:", avg, "°C")
    print("Hot readings:", hot_count)
💡 Key Insight:

Notice how the Mojo version uses def main() — in Mojo, the entry point is a regular function, not a script. Every .mojo file can contain multiple functions, but main() is what the compiler targets when you run mojo file.mojo. A Python script would instead run top-level statements in order, and its per-row output would be an f-string like f"{temp}°C → {category}"; the Mojo pane gets the same line by passing the values as separate print arguments, so no interpolation is needed at all.
