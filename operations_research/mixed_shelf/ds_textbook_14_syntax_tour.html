🔀 Mojo vs Python: A Syntax Tour

Six algorithms written idiomatically in Mojo 1.x, with the Python habit each one replaces called out in prose. If you already know Python, this chapter is a fast way to feel at home in Mojo.

Mojo borrows shapes from Python — but it isn't a copy. This chapter walks through six common algorithms: mathematical functions, financial formulas, and classic loops, each one a single Mojo program, with the Python habit it replaces noted in prose.

We won't explain every line — the point is pattern-matching. Notice where Mojo reads exactly like Python, where it adds types and explicit mutability, and where it's doing something Python doesn't.

1. Quadratic Equation Solver

Solving ax² + bx + c = 0 using the quadratic formula. This is a simple function that takes coefficients and returns the two roots — or signals that there are no real roots.

quadratic.mojo
from math import sqrt

def solve_quadratic(a: Float64, b: Float64, c: Float64) -> String:
    var discriminant = b * b - 4.0 * a * c
    if discriminant < 0.0:
        return "No real roots"
    var sqrt_disc = sqrt(discriminant)
    var r1 = (-b + sqrt_disc) / (2.0 * a)
    var r2 = (-b - sqrt_disc) / (2.0 * a)
    return "x1 = " + str(r1) + ", x2 = " + str(r2)

def main():
    print(solve_quadratic(1.0, -5.0, 6.0))   # x1 = 3.0, x2 = 2.0
    print(solve_quadratic(1.0, 2.0, 5.0))   # No real roots

Like Python, Mojo uses indentation — not curly braces — to delimit blocks. Mojo's var declaration is mandatory where Python's plain assignment just creates a name. Mojo's str() conversion mirrors Python's built-in str() for formatting output.

2. Compound Interest

The formula A = P(1 + r/n)^(nt) calculates the future value of an investment. This example shows loops, type annotations, and formatted output.

compound.mojo
from std.math import pow

def compound_interest(
    principal: Float64,
    rate: Float64,
    times_per_year: Int,
    years: Int
) -> Float64:
    var n = Float64(times_per_year)
    var t = Float64(years)
    return principal * pow(1.0 + rate / n, n * t)

def show_growth(principal: Float64, rate: Float64, years: Int):
    for y in range(1, years + 1):
        var amount = compound_interest(principal, rate, 12, y)
        print("Year ", y, ": $", amount)

def main():
    show_growth(10000.0, 0.05, 5)

Mojo's range(1, years + 1) is identical to Python's — both produce the same inclusive sequence and the same output.

3. Net Present Value (NPV)

NPV discounts a series of future cash flows to the present. It requires a loop that accumulates a sum — a perfect comparison of iteration styles.

npv.mojo
def npv(rate: Float64, cashflows: List[Float64]) -> Float64:
    var total: Float64 = 0.0
    for i in range(len(cashflows)):
        total += cashflows[i] / pow(1.0 + rate, Float64(i))
    return total

def main():
    var flows = List[Float64](-1000.0, 300.0, 420.0, 680.0)
    var result = npv(0.10, flows)
    print("NPV = $", result)
🔑 Key difference

Mojo's loop is Python-shaped: index with range(len(...)), accumulate with var. There is no enumerate, so the loop walks indices and casts the discount exponent with Float64(i) instead of using it bare. Same shape you already know, compiled to native code.

4. Simultaneous Equations (2×2)

Solving ax + by = e and cx + dy = f using Cramer's rule. This shows how each language handles math expressions, conditionals for degenerate cases, and multiple return values.

solve_2x2.mojo
struct Solution:
    var x: Float64
    var y: Float64

def solve_2x2(
    a: Float64, b: Float64, e: Float64,
    c: Float64, d: Float64, f: Float64
) -> Solution:
    var det = a * d - b * c
    if abs(det) < 1e-12:
        print("Degenerate — no unique solution")
        return Solution(0.0, 0.0)
    var x = (e * d - b * f) / det
    var y = (a * f - e * c) / det
    return Solution(x, y)

def main():
    var s = solve_2x2(2.0, 3.0, 8.0, 5.0, -2.0, 7.0)
    print("x =", s.x, "y =", s.y)

Mojo's struct lives on the stack with no heap allocation by default — a compiled-data version of Python's @dataclass, without the runtime overhead.

5. Factorial — Loops vs Recursion

Two implementations: iterative and recursive. This highlights how Mojo handles loops, recursion, and type safety for natural numbers.

factorial.mojo
def factorial_iter(n: Int) -> Int:
    var result: Int = 1
    for i in range(2, n + 1):
        result *= i
    return result

def factorial_rec(n: Int) -> Int:
    if n <= 1:
        return 1
    return n * factorial_rec(n - 1)

def main():
    for i in range(11):
        print(i, "! =", factorial_iter(i))
📝 Type note

Python's int is arbitrary precision — it grows as needed. Mojo uses a fixed-width signed Int for simplicity; the compiler will optimize either way. Both produce identical results for the range shown here.

6. Fibonacci Sequence

Generating the first N Fibonacci numbers. This shows list/array construction, mutable state in loops, and how Mojo handles growing collections.

fibonacci.mojo
def fibonacci(n: Int) -> List[Int]:
    var seq = List[Int]()
    var a: Int = 0
    var b: Int = 1
    for _ in range(n):
        seq.append(a)
        var temp = a + b
        a = b
        b = temp
    return seq

def main():
    var fib = fibonacci(15)
    for i in range(len(fib)):
        print("fib[", i, "] =", fib[i])

Python's one-line tuple swap a, b = b, a + b has no Mojo equivalent: assignment is a single binding, so the loop threads a var temp variable instead. The output is the same either way: 0, 1, 1, 2, 3, 5, 8, ...

💡 The takeaway

Mojo is intentionally readable for Python developers — you can often guess what Mojo code does just by knowing Python. But behind the scenes, every type annotation, var declaration, and ownership convention gives the compiler the information it needs to generate native code that runs far faster than an interpreter. That's the synthesis this book is about.
