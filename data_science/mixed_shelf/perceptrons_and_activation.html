The Perceptron

The simplest neural network and the foundation of deep learning.

1.1 Overview

The Perceptron, invented by Frank Rosenblatt in 1958, is the simplest type of artificial neural network. It is a linear binary classifier.

A perceptron takes multiple inputs, multiplies them by corresponding weights, adds a bias, and passes the result through an activation function.

Step 1: Compute the weighted sum (linear combination)

z = w · x + b

This expands to:

z = Σi=1n (wi · xi) + b

Step 2: Apply the activation function

ŷ = f(z)

Variable meanings:

  • x1, x2, …, xn are the input features
  • w1, w2, …, wn are the weights (importance of each input)
  • b is the bias (an offset value)
  • z is the weighted sum (linear combination)
  • f is the activation function

1.2 The Step Function

The traditional perceptron uses a "Step Function" to make a binary decision (0 or 1):

f(z) = { 1  if  z ≥ 0   ;   0  otherwise }

1.3 The Perceptron Learning Algorithm

The perceptron learns by adjusting its weights and bias when it makes a mistake. For each training sample (xi, yi):

Step 1: Compute the output

ŷi = f(w · xi + b)

Step 2: Check for misclassification

If ŷi = yi, do nothing. If ŷi ≠ yi, update the weights:

Update the weights:

w ← w + η (yi - ŷi) xi

Update the bias:

b ← b + η (yi - ŷi)

Here, η (eta) is the learning rate — a small positive number that controls how much we adjust the weights.

Repeat until convergence (no errors) or a maximum number of epochs.

Convergence guarantee (Novikoff, 1963): if the data are linearly separable with margin γ (the distance from the separating hyperplane to the nearest point) and all inputs satisfy ‖x‖ ≤ R, then the number of mistakes is bounded before convergence:

#mistakes ≤ ( R / γ )2

Note what the bound does not depend on: the learning rate (it rescales the weights, not the decisions), the number of features, or the number of samples. And if the data are not separable, no bound exists — the weights cycle forever, which is why the implementation caps epochs.

1.4 Implementation

Let's build a perceptron from scratch and train it to learn the logical AND gate:

from std.math import sqrt, exp, min, max
from std.collections import List

struct Perceptron:
    var lr: Float64
    var epochs: Int
    var weights: List[Float64]
    var bias: Float64

    def __init__(out self, learning_rate: Float64 = 0.1, epochs: Int = 100):
        self.lr = learning_rate
        self.epochs = epochs
        self.weights = List[Float64]()
        self.bias = 0.0

    def step_function(self, z: Float64) -> Int:
        """The activation function for a standard perceptron."""
        if z >= 0.0:
            return 1
        return 0

    def fit(mut self, X: List[List[Float64]], y: List[Int]):
        var n_features = X[0].size
        
        # Initialize weights to zeros
        self.weights = List[Float64]()
        for i in range(n_features):
            self.weights.append(0.0)
        self.bias = 0.0

        for _ in range(self.epochs):
            var errors = 0
            for idx in range(len(X)):
                var x_i = X[idx]
                
                # Linear combination
                var z = self.bias
                for j in range(n_features):
                    z += self.weights[j] * x_i[j]
                
                var y_predicted = self.step_function(z)
                
                # Update if misclassified
                var update = self.lr * Float64(y[idx] - y_predicted)
                if update != 0.0:
                    for j in range(n_features):
                        self.weights[j] += update * x_i[j]
                    self.bias += update
                    errors += 1
            
            if errors == 0:
                break

    def predict(self, X: List[List[Float64]]) -> List[Int]:
        var results = List[Int]()
        for idx in range(len(X)):
            var z = self.bias
            for j in range(self.weights.size):
                z += self.weights[j] * X[idx][j]
            results.append(self.step_function(z))
        return results

# --- Test the Perceptron (Logical AND Gate) ---
def main():
    var X = List[List[Float64]]()
    X.append([0.0, 0.0])
    X.append([0.0, 1.0])
    X.append([1.0, 0.0])
    X.append([1.0, 1.0])
    
    var y = List[Int]()
    y.append(0)
    y.append(0)
    y.append(0)
    y.append(1)

    var p = Perceptron(learning_rate=0.1, epochs=10)
    p.fit(X, y)

    print("Perceptron Predictions for AND gate:")
    var predictions = p.predict(X)
    for idx in range(len(X)):
        print(X[idx], "->", predictions[idx])

1.5 Visualizing the Decision Boundary

def plot_decision_boundary(
    X: List[List[Float64]], 
    y: List[Int], 
    weights: List[Float64], 
    bias: Float64
) raises:
    """Plot the decision boundary using matplotlib via Python interop."""
    var plt = Python.import_module("matplotlib.pyplot")
    var np = Python.import_module("numpy")
    
    # Convert Mojo lists to numpy arrays
    var X_np = np.array(X)
    var y_np = np.array(y)
    
    # Plot data points
    plt.scatter(X_np[:, 0], X_np[:, 1], c=y_np, cmap="viridis", edgecolors="k", s=100)
    plt.xlabel("x1")
    plt.ylabel("x2")
    
    # Compute decision boundary: w1*x1 + w2*x2 + b = 0
    var w1 = weights[0]
    var w2 = weights[1]
    var x1_vals = np.linspace(-0.5, 1.5, 100)
    var x2_vals = -(w1 * x1_vals + bias) / w2
    
    plt.plot(x1_vals, x2_vals, "r--", label="Decision boundary")
    plt.xlim(-0.5, 1.5)
    plt.ylim(-0.5, 1.5)
    plt.legend()
    plt.title("Perceptron Decision Boundary (AND Gate)")
    plt.show()

Activation Functions

The non-linear functions that enable neural networks to learn complex patterns.

While the step function is great for simple binary classification, it cannot be used in Deep Learning because its derivative is either 0 or undefined, meaning gradients cannot flow backward to update weights (the vanishing gradient problem).

Modern networks use differentiable, non-linear activation functions.

📊

Sigmoid

Outputs between 0 and 1. Great for binary classification output layers.

📐

Tanh

Zero-centered, outputs between -1 and 1. Often better than sigmoid for hidden layers.

⚡

ReLU

The most popular choice. Fast, efficient, and solves vanishing gradients.

🎯

Softmax

Converts logits to probabilities. Essential for multi-class classification.

2.1 Sigmoid (Logistic) Function

Squashes values between 0 and 1. Historically used in hidden layers of early neural networks and the output layer for binary classification.

Equation:

σ(z) = 1 / (1 + e−z)

Derivative (needed for backpropagation):

σ′(z) = σ(z) · (1 − σ(z))

Vanishing gradient, quantified. The derivative peaks at ¼ for z = 0 and decays exponentially:

σ′(0) = 0.25,   σ′(±5) ≈ 6.6×10−3,   σ′(±10) ≈ 4.5×10−5

Stack L sigmoid layers and the gradient reaching the first layer scales as 0.25L — at L = 10 that is already below 10−6. This single product is why deep networks abandoned sigmoid hidden layers for ReLU (derivative exactly 1 for z > 0, no decay).

2.2 Tanh (Hyperbolic Tangent)

Squashes values between -1 and 1. It is zero-centered, which often makes optimization easier than Sigmoid.

Equation:

tanh(z) = (ez − e−z) / (ez + e−z)

Derivative:

tanh′(z) = 1 − tanh2(z)

2.3 ReLU (Rectified Linear Unit)

The most popular activation function for hidden layers in modern deep learning. It is computationally efficient and helps mitigate the vanishing gradient problem.

Equation:

f(z) = max(0, z)

Derivative:

f′(z) = { 1  if  z > 0   ;   0  if  z ≤ 0 }

2.4 Leaky ReLU

A variant of ReLU that allows a small, non-zero gradient when the unit is not active, solving the "dying ReLU" problem.

Equation:

f(z) = max(0.01z, z)

Derivative:

f′(z) = { 1  if  z > 0   ;   0.01  if  z ≤ 0 }

2.5 Softmax

Used exclusively in the output layer for multi-class classification. It converts a vector of raw scores (logits) into a probability distribution where all probabilities sum to 1.

Equation:

σ(zi) = ezi / Σk=1K ezk

Key property: The output probabilities always sum to 1: Σi=1K σ(zi) = 1

The gradient you actually use: paired with cross-entropy loss L = −Σk yk log pk, the softmax Jacobian collapses to one line:

∂L / ∂zi = pi − yi

This is why every framework pairs softmax with cross-entropy — the ugly full Jacobian ∂pi/∂zj = pi(δij − pj) never needs to be formed explicitly.

Numerical stability rule: always subtract the max logit first (the implementation below does): softmax(z) = softmax(z − max(z)) — mathematically identical, but ez no longer overflows.

2.6 Implementation

from std.math import exp, min, max
from std.collections import List

# --- 1. Sigmoid ---
def sigmoid(z: Float64) -> Float64:
    """Sigmoid activation function."""
    var clamped = min(max(z, -500.0), 500.0)  # Prevent overflow
    return 1.0 / (1.0 + exp(-clamped))

def sigmoid_derivative(z: Float64) -> Float64:
    """Derivative of sigmoid: s * (1 - s)."""
    var s = sigmoid(z)
    return s * (1.0 - s)

# --- 2. Tanh ---
def tanh_act(z: Float64) -> Float64:
    """Hyperbolic tangent activation."""
    return (exp(z) - exp(-z)) / (exp(z) + exp(-z))

def tanh_derivative(z: Float64) -> Float64:
    """Derivative of tanh: 1 - tanh^2(z)."""
    var t = tanh_act(z)
    return 1.0 - t * t

# --- 3. ReLU ---
def relu(z: Float64) -> Float64:
    """Rectified Linear Unit."""
    return max(0.0, z)

def relu_derivative(z: Float64) -> Float64:
    """Derivative of ReLU."""
    if z > 0.0:
        return 1.0
    return 0.0

# --- 4. Leaky ReLU ---
def leaky_relu(z: Float64, alpha: Float64 = 0.01) -> Float64:
    """Leaky ReLU activation."""
    if z > 0.0:
        return z
    return alpha * z

def leaky_relu_derivative(z: Float64, alpha: Float64 = 0.01) -> Float64:
    """Derivative of Leaky ReLU."""
    if z > 0.0:
        return 1.0
    return alpha

# --- 5. Softmax ---
def softmax(z: List[Float64]) -> List[Float64]:
    """Softmax function - converts logits to probabilities."""
    var result = List[Float64]()
    
    # Find max for numerical stability
    var max_val = z[0]
    for val in z:
        if val > max_val:
            max_val = val
    
    # Compute exp(z - max) and sum
    var exp_sum = 0.0
    for val in z:
        var exp_val = exp(val - max_val)
        result.append(exp_val)
        exp_sum += exp_val
    
    # Normalize
    for i in range(result.size):
        result[i] = result[i] / exp_sum
    
    return result

# --- Testing the Functions ---
def main():
    var test_input = List[Float64]()
    test_input.append(-2.0)
    test_input.append(-1.0)
    test_input.append(0.0)
    test_input.append(1.0)
    test_input.append(2.0)

    print("Input:       ", test_input)
    
    # Test each function
    var sig_results = List[Float64]()
    var tanh_results = List[Float64]()
    var relu_results = List[Float64]()
    var leaky_results = List[Float64]()
    
    for val in test_input:
        sig_results.append(sigmoid(val))
        tanh_results.append(tanh_act(val))
        relu_results.append(relu(val))
        leaky_results.append(leaky_relu(val))
    
    print("Sigmoid:     ", sig_results)
    print("Tanh:        ", tanh_results)
    print("ReLU:        ", relu_results)
    print("Leaky ReLU:  ", leaky_results)
    print("Softmax:     ", softmax(test_input))

Numeric Tour

Every function and its derivative at the same sample points — the numbers behind the curves.

Run every activation and its derivative over the same grid and read the table: this is the numeric content of all the plots, and it exposes the behaviors that matter — saturation, zero-centering, gradient decay:

from std.math import exp, tanh, max
from std.collections import List

def main():
    var z = List[Float64]([-6.0, -2.0, -0.5, 0.0, 0.5, 2.0, 6.0])
    print("    z  |  sigmoid     σ′   |   tanh      t′   |  relu  r′  |  leaky")
    for i in range(len(z)):
        var v = z[i]
        var s = 1.0 / (1.0 + exp(-v))          # sigmoid
        var t = tanh(v)
        var leaky = max(0.01 * v, v)
        print(v, " |", s, s * (1.0 - s),
              "|", t, 1.0 - t * t,
              "|", max(0.0, v), "|", leaky)
    # σ′(±6) ≈ 0.0025: saturated.  t′(0) = 1 vs σ′(0) = 0.25.
    # ReLU: gradient exactly 1 for z > 0 — never decays.
Gradient decay through depth: with L layers, the backprop product is Π f′(z˧) — sigmoid: bounded by 0.25L; tanh: 1L at best but decays off-center; ReLU: exactly 1 while active. That product is the whole vanishing-gradient story in one line.

Limitations

Why we need more than a single perceptron.

The perceptron is a linear classifier—it can only solve problems that are linearly separable. The classic XOR problem cannot be solved with a single perceptron:

Input (x1, x2) AND OR XOR
(0, 0)000
(0, 1)011
(1, 0)011
(1, 1)110

For non-linear problems, we need multi-layer perceptrons (neural networks) with non-linear activation functions (like sigmoid, ReLU) and techniques like backpropagation.

Why XOR is provably impossible (the convex-hull argument): a perceptron separates the classes with a hyperplane w·x + b = 0. Two classes are separable by a hyperplane if and only if their convex hulls do not intersect. For XOR:

conv{(0,0), (1,1)} ∩ conv{(0,1), (1,0)} = {(½, ½)} ≠ ∅

The hulls are the two diagonals of the unit square — they cross at the center. No hyperplane exists, so by the Novikoff bound (Chapter 1) the learning rule never converges; it cycles forever.

What breaks the linearity: stacking layers with a non-linear activation gives the universal approximation form:

f(x) = W2 · σ( W1x + b1 ) + b2

Without σ (or any non-linearity) the composition W2W1x collapses to a single linear map — a multi-layer linear network is still just one perceptron. The activation function is the only thing that adds expressive power; the layers just arrange it. XOR needs exactly one hidden layer with two units.

All Functions & Derivatives

step:  f(z) = [z ≥ 0],   f′ = undefined  →  perceptrons only

sigmoid:  σ(z) = 1/(1+e−z),   σ′ = σ(1−σ) ≤ 0.25  →  binary output layer

tanh:  tanh(z),   tanh′ = 1 − tanh2 ≤ 1  →  RNN/LSTM hidden layers

ReLU:  max(0, z),   f′ = [z > 0] ∈ {0, 1}  →  default hidden layer

Leaky ReLU:  max(αz, z),   f′ ∈ {α, 1}  →  when ReLU units die

softmax:  pi = ezi/Σezk,   ∂L/∂zi = pi − yi (with cross-entropy)  →  multi-class output layer
Gradient products through depth: backprop multiplies derivatives: Π f′(z˧) — bounded by 0.25L (sigmoid), decaying off-center (tanh), exactly 1 while active (ReLU). This one product decides which activations survive depth.
