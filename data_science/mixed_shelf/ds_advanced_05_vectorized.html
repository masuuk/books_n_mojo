SIMD instructions, parallelized loops, views, element-wise operations, and broadcasting — writing code that maps directly to hardware.

SIMD: One Instruction, Many Values

SIMD (Single Instruction, Multiple Data) lets a CPU process 4, 8, or 16 values simultaneously with a single instruction. Mojo has first-class SIMD support via the SIMD type, which maps directly to vector registers on the CPU.

Mojo
# SIMD: process 8 floats simultaneously
from math import sqrt

def simd_dot(a: Pointer[Float32],
             b: Pointer[Float32],
             n: Int) -> Float32:
    var sum = SIMD[DType.float32, 8](0)  # 8-wide SIMD register
    var i = 0

    # Process 8 elements per iteration
    while i + 8 <= n:
        var va = a.simd_load[8](i)
        var vb = b.simd_load[8](i)
        sum += va * vb  # 8 multiply-adds in one instruction
        i += 8

    # Horizontal sum
    var result = sum.reduce_add()

    # Handle remaining elements
    while i < n:
        result += a[i] * b[i]
        i += 1

    return result

# Vectorized ReLU — 16 floats at a time
def simd_relu(data: Pointer[Float32], n: Int):
    var zero = SIMD[DType.float32, 16](0)
    var i = 0
    while i + 16 <= n:
        var vals = data.simd_load[16](i)
        data.simd_store[16](i, vals.max(zero))
        i += 16
    while i < n:
        data[i] = max(data[i], 0)
        i += 1
SIMD width auto-detection:

Mojo's SIMD type parameterizes on both dtype and width. The compiler can auto-select the optimal width for the target CPU: 4-wide on SSE, 8-wide on AVX2, 16-wide on AVX-512.

ParallelFor: Automatic Multi-Threading

Mojo's parallelize (or parallel_for) automatically distributes loop iterations across available CPU cores. Combined with SIMD, this gives you both data-level parallelism (SIMD) and thread-level parallelism (multi-core).

Mojo
# Parallel element-wise operations
def parallel_scale(
    src: Pointer[Float32],
    dst: Pointer[Float32],
    n: Int,
    scale: Float32
):
    # Distribute across all CPU cores
    for i in parallelize(n):
        dst[i] = src[i] * scale

# Parallel matrix multiplication (simple version)
def parallel_matmul(
    A: Tensor[Float32],
    B: Tensor[Float32],
    C: Tensor[Float32],
    M: Int, N: Int, K: Int
):
    # Parallelize over rows of output
    for i in parallelize(M):
        for j in range(N):
            var acc = SIMD[DType.float32, 8](0)
            var k = 0
            while k + 8 <= K:
                var a = A[i, k:k+8]
                var b = B[k:k+8, j]
                acc += a * b.simd_broadcast[8]()
                k += 8
            C[i, j] = acc.reduce_add()

# Parallel reduction — sum an array
def parallel_sum(data: Tensor[Float32]) -> Float32:
    var n = data.size()
    var num_tasks = 8
    var partial = Tensor[Float32](num_tasks)

    # Each thread sums its chunk
    for t in parallelize(num_tasks):
        var start = t * (n // num_tasks)
        var end = (t + 1) * (n // num_tasks)
        var local_sum = 0
        for i in range(start, end):
            local_sum += data[i]
        partial[t] = local_sum

    # Final reduction (single-threaded)
    var total: Float32 = 0
    for t in range(num_tasks):
        total += partial[t]
    return total
Built-in parallelism:

Mojo's parallelize is built into the language — no external libraries or thread-management boilerplate required. The compiler automatically handles thread pool management, work stealing, and task granularity.

Views: Zero-Copy Slicing and Reshaping

A View in Mojo is a lightweight reference to a contiguous memory region. It doesn't own the data — it's a "view" into existing tensor memory. This enables zero-copy slicing, reshaping, and transposing.

Mojo
# Views — zero-copy slicing and reshaping
from tensor import Tensor, TensorSpec

def process_rows():
    var t = Tensor[Float32](100, 10)  # 100 rows, 10 cols

    # Slice — creates a view, no data copy
    var row5 = t[5, :]        # View of row 5
    var col3 = t[:, 3]        # View of column 3
    var block = t[10:20, 2:8]  # View of a sub-block

    # Reshape — also zero-copy
    var flat = t.reshape[1000]()

    # Transpose — zero-copy (swaps strides)
    var transposed = t.T  # View of shape (10, 100)

# Mutable views for in-place transformation
def normalize_rows(mut t: Tensor[Float32]):
    for i in range(t.dim[0]):
        var row = t[i, :]       # View of row i
        var mean = row.reduce_add() / Float32(t.dim[1])
        var std = row.std()
        t[i, :] = (row - mean) / std  # In-place via view

Broadcasting: Implicit Shape Alignment

Broadcasting allows operations between tensors of different shapes without explicit loops. Mojo automatically expands dimensions to match, following rules similar to NumPy but with compile-time shape checking.

Mojo
# Broadcasting — implicit shape alignment
def broadcast_add():
    var a = Tensor[Float32](4, 3)  # shape (4, 3)
    var b = Tensor[Float32](3)     # shape (3,)

    # b is broadcast to (4, 3) automatically
    var result = a + b

    # Adding a column vector to a matrix
    var matrix = Tensor[Float32](100, 64)  # (100, 64)
    var bias = Tensor[Float32](1, 64)       # (1, 64)
    var output = matrix + bias               # broadcast along axis 0

# Element-wise operations with broadcasting
def normalize_batch(batch: Tensor[Float32]) -> Tensor[Float32]:
    # batch shape: (N, C, H, W)
    var means = batch.mean(axis=1)  # shape: (N, 1, H, W)
    var stds = batch.std(axis=1)    # shape: (N, 1, H, W)

    # Broadcasting: (N, C, H, W) - (N, 1, H, W) / (N, 1, H, W)
    return (batch - means) / stds
Mojo's advantage:

Mojo checks broadcasting shapes at compile time. If shapes are incompatible, you get a compile error — not a runtime crash like NumPy. This catches bugs before the code even runs.
