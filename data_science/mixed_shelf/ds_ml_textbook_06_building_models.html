Implementing neural networks from scratch in Mojo — forward passes, backpropagation, and training loops that rival PyTorch.

From NumPy to Mojo Tensors

Before we build a neural network, we need efficient tensor operations. In Python, numpy gives us vectorized array math. In Mojo, we get the same expressiveness with compiled performance — no C extension boundary, no GIL, no Python overhead.

A tensor in Mojo is a contiguous block of memory with shape metadata. Unlike NumPy, which hides allocation behind np.array(), Mojo lets you own the memory directly and choose exactly when copies happen.

💡 Key Insight:

Mojo's Tensor type carries element type at compile time. The compiler can optimize shape checks and memory layout, eliminating runtime overhead that Python frameworks pay on every operation.

from tensor import Tensor
from math import sqrt

def matmul(
    A: Tensor[Float32], B: Tensor[Float32]
) -> Tensor[Float32]:
    var rows = A.shape()[0]
    var cols = B.shape()[1]
    var K = A.shape()[1]
    var C = Tensor[Float32](rows, cols)
    for i in range(rows):
        for j in range(cols):
            var acc: Float32 = 0.0
            for k in range(K):
                acc += A[i, k] * B[k, j]
            C[i, j] = acc
    return C

def relu(mut T: Tensor[Float32]):
    for i in range(T.num_elements()):
        if T[i] < 0.0:
            T[i] = 0.0

Mojo's Tensor[Float32] carries its element type at compile time, so the compiler knows the exact memory layout and can inline the math. Compare the two primitives above: in NumPy a matrix multiply is A @ B and a ReLU is np.maximum(T, 0.0) — one line each, delegated to the library. The Mojo versions are the triple loop and the element-wise clamp, written out. That extra length buys something specific: A.shape()[0] is a compile-time-known layout, the accumulator acc stays in a register across the innermost loop, and relu takes mut T so it clamps in place instead of allocating a second tensor the way the returning NumPy form must.

Essential Tensor Operations

A neural network needs tensor primitives: element-wise operations, summation, and activation functions. Let's build the two this chapter leans on — a loss and a softmax — as reusable functions.

from tensor import Tensor
from math import exp, log

def mse_loss(
    predictions: Tensor[Float32],
    targets: Tensor[Float32],
) -> Float32:
    var n = Float32(predictions.num_elements())
    var total: Float32 = 0.0
    for i in range(predictions.num_elements()):
        var diff = predictions[i] - targets[i]
        total += diff * diff
    return total / n

def softmax(mut logits: Tensor[Float32]):
    var n = logits.num_elements()
    var max_val: Float32 = logits[0]
    for i in range(1, n):
        if logits[i] > max_val:
            max_val = logits[i]
    var exp_sum: Float32 = 0.0
    for i in range(n):
        logits[i] = exp(logits[i] - max_val)
        exp_sum += logits[i]
    for i in range(n):
        logits[i] /= exp_sum
🚀 Pro Tip:

The numerically stable softmax (subtracting max_val before exponentiating) is critical to avoid overflow. Mojo's exp() compiles directly to the hardware intrinsic — no library overhead.

Neural Network from Scratch

With tensor ops in hand, we build a two-layer neural network for classification. We define weights as tensors, implement a forward pass with ReLU activation, and compute cross-entropy loss.

from tensor import Tensor
from math import sqrt

struct TwoLayerNet:
    var W1: Tensor[Float32]
    var b1: Tensor[Float32]
    var W2: Tensor[Float32]
    var b2: Tensor[Float32]

    def __init__(
        mut self,
        input_dim: Int, hidden_dim: Int, output_dim: Int,
    ):
        self.W1 = Tensor[Float32](input_dim, hidden_dim)
        self.b1 = Tensor[Float32](hidden_dim)
        self.W2 = Tensor[Float32](hidden_dim, output_dim)
        self.b2 = Tensor[Float32](output_dim)
        # Xavier initialization
        var scale1 = sqrt(2.0 / Float32(input_dim))
        for i in range(self.W1.num_elements()):
            self.W1[i] = randn_float32() * scale1
        var scale2 = sqrt(2.0 / Float32(hidden_dim))
        for i in range(self.W2.num_elements()):
            self.W2[i] = randn_float32() * scale2

    def forward(self, X: Tensor[Float32]) -> Tensor[Float32]:
        var h = matmul(X, self.W1)
        for i in range(h.num_elements()):
            h[i] += self.b1[i % self.b1.shape()[0]]
        relu(h)
        var out = matmul(h, self.W2)
        for i in range(out.num_elements()):
            out[i] += self.b2[i % self.b2.shape()[0]]
        softmax(out)
        return out
⚠️ Watch Out:

The Mojo example uses manual loops for bias addition to demonstrate low-level control. In production, wrap common operations into utility functions to keep code clean and avoid off-by-one errors.

Worth naming what PyTorch was doing for you. As an nn.Module, TwoLayerNet gets nn.Linear layers, parameter registration, and the whole super().__init__() protocol for free — two lines of constructor become a full framework contract. The struct TwoLayerNet above has to spell out all four tensors, initialize them by hand, and write Xavier scaling inline. In exchange the tensors are compile-time typed, the forward pass is straight-line code with no dispatch layer, and nothing is hidden behind a .backward() you did not ask for.

Training Loops and Backpropagation

The training loop brings everything together: forward pass, loss computation, backward pass, and weight updates. Mojo's ownership model ensures gradient tensors don't accidentally alias forward-pass tensors — a common source of subtle bugs in Python autograd.

Manual Backpropagation

Let's write the backward pass by hand. We compute gradients for each weight tensor and update them with stochastic gradient descent.

from tensor import Tensor

def train_epoch(
    mut model: TwoLayerNet,
    X: Tensor[Float32],
    y: Tensor[Float32],
    lr: Float32,
) -> Float32:
    var probs = model.forward(X)
    # Cross-entropy loss
    var loss: Float32 = 0.0
    for i in range(probs.num_elements()):
        if y[i] > 0.0:
            loss -= y[i] * log(probs[i] + 1e-7)
    # Backward: dL/d(logits) = probs - one_hot(y)
    var d_logits = Tensor[Float32](probs.shape())
    for i in range(probs.num_elements()):
        d_logits[i] = probs[i] - y[i]
    # SGD weight update
    for i in range(model.W2.num_elements()):
        model.W2[i] -= lr * d_logits[i % d_logits.num_elements()]
    return loss
🚀 Pro Tip:

Mojo's mut parameter makes it explicit that train_epoch mutates the model. The compiler guarantees exclusive access to the tensors during the call, which prevents the aliasing bugs that can appear in Python autograd.

The same idea replaces the torch.no_grad() block. PyTorch needs that guard because gradients are recorded by default and stepping them means walking model.parameters(), updating p.grad, and calling p.grad.zero_() so the next epoch does not accumulate on top of it. The Mojo update has no tape to manage: d_logits is an ordinary local tensor, the SGD step touches model.W2 through a mut parameter, and there is nothing to zero out.

Model Evaluation

After training, we measure generalization on held-out data. Here's a complete evaluation routine that computes accuracy.

from tensor import Tensor

def accuracy(
    model: TwoLayerNet,
    X_test: Tensor[Float32],
    y_test: Tensor[Float32],
) -> Float32:
    var probs = model.forward(X_test)
    var correct: Int = 0
    var total = probs.shape()[0]
    var nc = probs.shape()[1]
    for i in range(total):
        var pred_class: Int = 0
        var best: Float32 = probs[i * nc]
        for c in range(1, nc):
            if probs[i * nc + c] > best:
                best = probs[i * nc + c]
                pred_class = c
        if Float32(pred_class) == y_test[i]:
            correct += 1
    return Float32(correct) / Float32(total)

var acc = accuracy(model, X_test, y_test)
print("Test accuracy:", acc * 100.0, "%")
💡 Key Insight:

In production, Mojo's compiled evaluation loop runs inference on thousands of samples per second without the Python GIL bottleneck. The same binary that trains your model can serve predictions with zero interpreter overhead.

Worth comparing the shape of the two evaluation routines. The scikit-learn version is four lines because model.eval(), torch.no_grad(), probs.argmax(dim=1), and accuracy_score(y_test, preds) each do a whole stage for you. The Mojo version spells out the two stages that were hidden — find the arg-max over the class axis, then count the matches — and the inner loop is where the compile-time shape pays off: nc is loaded once, and the row start i * nc is arithmetic on a known layout rather than a stride lookup.
