A 3–4–1 neural network, in Mojo 1.x and in NumPy

The same 40‑line network, twice: once leaning on NumPy's array slicing and .dot(), once built from a hand‑written matrix struct and a hand‑rolled PRNG. Every number on this page was produced by running the code.

Mojo 1.x NumPy no dependencies in the Mojo version 60 epochs, both converge

The program below trains a small feedforward network on four examples. There is nothing clever about the network. What is interesting is how little of NumPy it actually needs — and how much Mojo 1.x asks you to write yourself, which turns out to be a good way to see what the matrix operations were doing all along.

The problem ↑

Four examples go in, one number comes out. The third input is always 1.0, so it is really just a bias. That leaves two meaningful inputs, and those two follow XOR: high when exactly one of them is set.

XOR is the classic example of a pattern no single unit can represent, because the classes are not linearly separable. Give a network that shape and it will sit at a loss of about 1.0 forever, no matter how long you train it. Add one hidden layer and the problem becomes easy.

Three routes to this same target. You are about to build a 3–4–1 ReLU network with no dependencies. Neural Network from Scratch does the same four examples with a 2–2–1 sigmoid network and grows the perceptron on the way; MLP XOR Lab uses a 2–4–1 and adds a neuron that learns to add. And Perceptrons & Activations is the theory underneath all three.

The network ↑

Three inputs, four ReLU units, one linear output. Sixteen weights, no bias terms, a learning rate of 0.2, and plain per‑example stochastic gradient descent: one update per example, 60 epochs, 240 updates in total.

One correction to the obvious reading. The comments in the original call the third input “output”, which is easy to misread. It is an input. The actual targets live in a separate array called strike, and the network's prediction is what the code calls layer_2.

Both programs, in full ↑

Here they are side by side. The Python is the original as written; the Mojo is a faithful port, keeping the same architecture, the same hyper‑parameters, and the same per‑example update order.

This is a one‑off port, not a method. A full NumPy‑to‑Mojo translation guide, covering what happens to array slicing, broadcasting and the .dot() call, is Python → Mojo Numerical Computing. What follows is one network carried across by hand.

193struct Net(Copyable, Movable):
194    """A one-hidden-layer network, trained one example at a time.
195 
196    There are no bias terms, because the third input is a constant 1.0
197    and is doing that job -- the same trick the NumPy version uses.
198    """
199

201    var W1_2: Matrix  # (hidden x 1)

203 
204    def __init__(out self, n_in: Int, n_hidden: Int, mut rng: XorShift, alpha: Float64):
205        self.alpha = alpha
206        self.W0_1 = Matrix.rand_small(n_in, n_hidden, rng, 2.0)
207        self.W1_2 = Matrix.rand_small(n_hidden, 1, rng, 2.0)
208 
209    def forward(self, x: Matrix) -> (Matrix, Matrix):
210        """x is (n_in x 1). Returns (a1, z2) -- the hidden activation and
211        the raw output, both before any weight update."""
212        # z1 = W0_1^T @ x   ->  (hidden x 1)
213        var z1 = self.W0_1.transpose().matmul(x)
214        # a1 = relu(z1)
215        var a1 = relu_m(z1)
216        # z2 = W1_2^T @ a1  ->  (1 x 1)
217        var z2 = self.W1_2.transpose().matmul(a1)
218        return (a1^, z2^)
219 
220    def train_step(mut self, x: Matrix, target: Float64) -> Float64:
221        """One forward pass, one backpropagation pass, one SGD step.
222        Returns the squared error for this example."""
223        # --- forward ------------------------------------------------------
224        var z1 = self.W0_1.transpose().matmul(x)
225        var a1 = relu_m(z1)
226        var z2 = self.W1_2.transpose().matmul(a1)
227 
228        # --- how wrong were we --------------------------------------------
229        var diff = z2.get(0, 0) - target
230        var delta2 = Matrix.zeros(1, 1)
231        delta2.set(0, 0, diff)
232 
233        # --- backpropagation ----------------------------------------------
234        #   delta1 = (W1_2 @ delta2) * relu'(z1)
235        #
236        # The NumPy original writes this as
237        #     layer_1_delta = layer_2_delta.dot(weights_1_2.T) * relu2deriv(layer_1)
238        # which is the same product with the transpose on the other side,
239        # and it is the element-wise multiply on the right that is
240        # ReLU's derivative. Skip that multiply and the gradient leaks
241        # through the dead units.
242        var delta1 = self.W1_2.matmul(delta2).mul(relu_mask(z1))
243 
244        # --- update ---------------------------------------------------------
245        # Both gradients are outer products: W1_2 moves along a1 by
246        # delta2, and W0_1 moves along x by delta1.
247        self.W1_2 = self.W1_2.sub(a1.outer(delta2).scalar_mul(self.alpha))
248        self.W0_1 = self.W0_1.sub(x.outer(delta1).scalar_mul(self.alpha))
249 
250        return diff * diff

3. The matrix type

This is the part NumPy hands you for free. A row‑major Matrix is a flat List[Float64] plus get/set, and the products are triple loops. Note that the examples are columns here, so the weight matrices are stored transposed relative to the original.

Worth knowing what you are imitating. That triple‑loop matmul is the whole reason this port is 193 lines instead of 40. Linear Algebra Engine builds the tiled, SIMD‑aware version, and Tensor Architecture covers the row‑major layout and shape arithmetic this struct invents by hand. Read this step once to see what the library hides, then go and use the library.

5. Backpropagation

The output delta is just the error, and the hidden delta is that error pushed backwards through W1_2 and then gated by ReLU's derivative. The gate is the one line worth reading twice: multiply by it, and a unit that is off sends no gradient and stops learning. Skip it, and dead units leak.

These four lines are the last time you write them by hand. Every derivative in this section is a transcription of the chain rule, which is exactly the job Autodiff & Optimization takes over: differentiate at compile time, then swap the plain SGD step for Adam.

6. The update

Both gradients are outer products, which is why a single column and a single column can update a whole weight matrix. NumPy writes weights -= alpha * a.T @ delta. Mojo spells the same idea as a.outer(delta).scalar_mul(alpha) — longer, but it names exactly which product is happening.

ReLU’s derivative is a gate ↑

ReLU is flat below zero, and its derivative is exactly zero there. So a hidden unit whose pre‑activation is negative passes no gradient at all, and the weights feeding it freeze. This is the same mechanism that makes a network get stuck: units switch off, and if the ones that switched off were the useful ones, there is no gradient left to bring them back.

Why it matters, and where to go next. A dead ReLU is the standard failure mode of a from‑scratch network, and it is why leaky variants and careful initialisation exist. Perceptrons & Activations works through the gate against the other common activations, and ML Fundamentals covers the optimiser side: learning rate, momentum, and why a stuck network is often a learning‑rate problem wearing a network's clothes.

What actually happened ↑

Both versions learned the pattern. The curves differ because the two versions draw their starting weights from different seeded generators, and XOR is genuinely sensitive to where you start — roughly half of all random starts get stuck.
