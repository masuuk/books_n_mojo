BLAS Wrappers in Mojo

The Basic Linear Algebra Subprograms (BLAS) define low-level routines for common operations like vector dot products, matrix-vector multiplication, and matrix-matrix multiplication. Mojo can call C BLAS routines directly through its FFI, giving you near-native performance with zero Python overhead.

Unlike Python's scipy.linalg which wraps BLAS through multiple abstraction layers, Mojo can call BLAS functions with zero marshaling cost. The compiler inlines small kernels and eliminates the GIL entirely.

Mojo 1.x
// Direct BLAS Level-3 call from Mojo
from math.linalg import matrix_multiply, Matrix
from sys.ffi import cblas_dgemm

var A = Matrix[Float64](64, 64)
var B = Matrix[Float64](64, 64)
var C = Matrix[Float64](64, 64)

// Fill A and B with values...
randomize(A)
randomize(B)

// C = alpha * A × B + beta * C
cblas_dgemm(
    CblasRowMajor, CblasNoTrans, CblasNoTrans,
    64, 64, 64,
    1.0, A.data(), 64,
    B.data(), 64,
    0.0, C.data(), 64
)
❓ Why this matters:

Python's BLAS calls go through ctypes → cffi → Fortran, adding ~2-5μs of overhead per call. Mojo's FFI compiles to a direct call instruction with zero runtime cost. For tight loops calling BLAS repeatedly, this adds up.

Tiled Matrix Multiplication

Naive matrix multiplication is O(n³) but cache-unfriendly. Tiled (blocked) multiplication divides the matrix into cache-sized blocks, dramatically improving data locality. This is the same technique used inside vendor BLAS implementations.

Why Tiling Works

A modern CPU L1 cache holds ~32KB. A 4096×4096 matrix of Float64 is 128MB — it won't fit. By dividing into tiles that fit in L1, we exploit temporal locality: each tile element is loaded once and reused many times before eviction.

Mojo 1.x
def tiled_matmul[
    TILE: Int = 64
](A: Matrix[Float64], B: Matrix[Float64]) -> Matrix[Float64]:
    var n = A.rows
    var C = Matrix[Float64](n, n)

    for i in range(0, n, TILE):
        for j in range(0, n, TILE):
            for k in range(0, n, TILE):
                // Multiply tile block (i:k) × (k:j)
                for ti in range(i, min(i + TILE, n)):
                    for tj in range(j, min(j + TILE, n)):
                        var sum = 0.0
                        for tk in range(k, min(k + TILE, n)):
                            sum += A[ti, tk] * B[tk, tj]
                        C[ti, tj] += sum
    return C
Mojo advantage:

Mojo's compile-time parameters let you set TILE as a compile-time constant. The compiler unrolls the inner loops and vectorizes them with SIMD automatically.

Matrix Operations Library

Beyond multiplication, a complete linear algebra engine needs decomposition routines, inversion, and element-wise operations. Mojo's math.linalg module provides a growing set of these primitives.

Key Operations

  • LU Decomposition: Factor A = LU with partial pivoting for solving linear systems.
  • QR Decomposition: Used in least-squares fitting and eigenvalue algorithms.
  • SVD: Singular Value Decomposition for dimensionality reduction and pseudo-inverses.
  • Cholesky: Efficient decomposition for symmetric positive-definite matrices.
Mojo 1.x
from math.linalg import (
    lu_decomposition,
    solve_triangular,
    matrix_inverse
)

def solve_linear_system(A: Matrix[Float64], b: Vector[Float64]) -> Vector[Float64]:
    // LU factorization with partial pivoting
    var (L, U, P) = lu_decomposition(A)

    // Solve Ly = Pb (forward substitution)
    var y = solve_triangular(L, P @ b, lower=True)

    // Solve Ux = y (back substitution)
    return solve_triangular(U, y, lower=False)


def matrix_norm(A: Matrix[Float64]) -> Float64:
    // Frobenius norm — fully vectorized
    return sqrt((A ** 2.0).sum())

Benchmark methodology:

All benchmarks run on the same hardware (Apple M2, 16GB RAM). Times are median of 100 runs after 10 warm-up iterations. NumPy uses OpenBLAS; Mojo uses its own tiled implementation.
