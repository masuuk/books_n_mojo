1. Coordinate Frames & Basic Geodesy

Brief

GNSS hands you Earth-centred Cartesian coordinates, maps are drawn on a projected grid, and levels are referred to a physical vertical datum. This chapter builds the conversion chain — geodetic ⇄ ECEF ⇄ local ENU — on the WGS84 ellipsoid. Every later chapter (calibration, georeferencing, point positioning) speaks in one of these three frames, so getting the chain right is what keeps a millimetre from becoming a metre.

GNSS positioning passes through several conceptual layers: satellite-frame observations → Earth-centred Earth-fixed (ECEF) Cartesian coordinates → geodetic latitude, longitude and ellipsoidal height → projected grid coordinates → local/site coordinates after localisation → orthometric heights after applying a geoid model.

1.1 The WGS84 ellipsoid

The single reference surface that defines latitude, longitude and ellipsoidal height worldwide — two numbers (a and f) from which everything else is derived.

a = 6 378 137.0 m  |  f = 1 / 298.257223563  |  e² = 2f − f²

These two constants are also the entry point to the projection half of the course: mapping ellipsoidal (φ, λ) onto a Transverse Mercator grid — UTM zones, Southern African LO belts — to sub-millimetre accuracy is developed in full in Part 2 — The Karney-Krüger Equations.

1.2 Geodetic ↔ ECEF

The forward conversion is closed-form; the inverse has no simple algebraic solution and is therefore iterated until the latitude converges.

From geodetic (φ, λ, h) to ECEF:

N = a / √(1 − e² sin²φ)   (radius of curvature in the prime vertical)
X = (N + h) cosφ cosλ
Y = (N + h) cosφ sinλ
Z = (N(1 − e²) + h) sinφ

The reverse (ECEF → geodetic) is usually solved iteratively.

MOJO 1.x — coordinate_transform.mojo 
from std.math import sqrt, sin, cos, atan2, hypot, radians, degrees, abs

comptime A: Float64 = 6378137.0
comptime F: Float64 = 1.0 / 298.257223563
comptime E2: Float64 = 2.0 * F - F * F

def geodetic_to_ecef(lat_deg: Float64, lon_deg: Float64, h: Float64)
        -> Tuple[Float64, Float64, Float64]:
    var lat = radians(lat_deg)
    var lon = radians(lon_deg)
    var sin_lat = sin(lat)
    var cos_lat = cos(lat)
    var sin_lon = sin(lon)
    var cos_lon = cos(lon)

    # prime-vertical radius of curvature
    var N = A / sqrt(1.0 - E2 * sin_lat * sin_lat)

    var x = (N + h) * cos_lat * cos_lon
    var y = (N + h) * cos_lat * sin_lon
    var z = (N * (1.0 - E2) + h) * sin_lat
    return (x, y, z)

def ecef_to_geodetic(x: Float64, y: Float64, z: Float64)
        -> Tuple[Float64, Float64, Float64]:
    var lon = atan2(y, x)
    var p = hypot(x, y)
    var lat = atan2(z, p * (1.0 - E2))
    var h: Float64 = 0.0
    for _ in range(10):
        var sin_lat = sin(lat)
        var N = A / sqrt(1.0 - E2 * sin_lat * sin_lat)
        h = p / cos(lat) - N
        var lat_new = atan2(z, p * (1.0 - E2 * N / (N + h)))
        if abs(lat_new - lat) < 1e-12:
            break
        lat = lat_new
    return (degrees(lat), degrees(lon), h)

def main():
    var x, y, z = geodetic_to_ecef(45.9764, 7.6586, 4478.0)
    print("ECEF:", x, y, z)
    var lat2, lon2, h2 = ecef_to_geodetic(x, y, z)
    print("Back:", lat2, "deg", lon2, "deg", h2, "m")

1.3 ECEF → local ENU (East, North, Up)

Rotating an ECEF difference vector into a horizon frame at a reference point — the natural way to express GNSS baselines, misclosures and residuals in metres you can point at.

Topocentric ENU coordinates at a reference point (φ₀, λ₀) are the natural frame for expressing local GNSS baselines and residuals:

[e n u]ᵀ = R · [ΔX ΔY ΔZ]ᵀ

R = [ −sinλ₀         cosλ₀          0 ]
    [ −sinφ₀cosλ₀   −sinφ₀sinλ₀   cosφ₀ ]
    [  cosφ₀cosλ₀    cosφ₀sinλ₀    sinφ₀ ]
MOJO 1.x — ecef_to_enu.mojo 
from std.math import sin, cos, radians

@fieldwise_init
struct Vec3:
    var x: Float64
    var y: Float64
    var z: Float64

@fieldwise_init
struct ENU:
    var e: Float64
    var n: Float64
    var u: Float64

def ecef_delta_to_enu(d: Vec3, lat0_deg: Float64, lon0_deg: Float64) -> ENU:
    """
    Rotate an ECEF difference vector into the local horizon frame
    at (lat0_deg, lon0_deg). The rotation is expanded component by
    component, so no matrix library is needed.
    """
    var lat0 = radians(lat0_deg)
    var lon0 = radians(lon0_deg)
    var sin_lat = sin(lat0)
    var cos_lat = cos(lat0)
    var sin_lon = sin(lon0)
    var cos_lon = cos(lon0)

    # row 1 of R: east = -sin(lon)*dX + cos(lon)*dY
    var e = -sin_lon * d.x + cos_lon * d.y
    # row 2 of R: north = -sin(lat)cos(lon)*dX - sin(lat)sin(lon)*dY + cos(lat)*dZ
    var n = -sin_lat*cos_lon * d.x - sin_lat*sin_lon * d.y + cos_lat * d.z
    # row 3 of R: up = cos(lat)cos(lon)*dX + cos(lat)sin(lon)*dY + sin(lat)*dZ
    var u =  cos_lat*cos_lon * d.x + cos_lat*sin_lon * d.y + sin_lat * d.z
    return ENU(e, n, u)

def main():
    # a 100 m step along the ECEF X axis, seen from 45 N, 8 E:
    # mostly north with a small up component, as expected at mid-latitude
    var enu = ecef_delta_to_enu(Vec3(100.0, 0.0, 0.0), 45.0, 8.0)
    print("ENU (m):", enu.e, enu.n, enu.u)
Ellipsoidal height ≠ orthometric height. GNSS naturally gives height relative to the reference ellipsoid. Surveying elevations refer to a physical vertical datum; a geoid model relates the two, approximately H = h − N under the usual convention.

2. Coordinate Transformations

Brief

A transformation changes the numbers that describe a point while preserving its physical location. This chapter covers the four models a surveyor actually uses — translation, 2D similarity (4-parameter), affine (6-parameter) and 3D Helmert (7-parameter) — how to choose between them from the control geometry, and how to estimate their parameters by least squares rather than by hand.

A coordinate transformation changes the numerical representation of a point while preserving its physical location according to a defined mathematical model and reference system. In surveying the most common are the 2D similarity / conformal (4-parameter) model, the affine (6-parameter) model, and the 3D Helmert 7-parameter transformation used between geodetic datums (e.g. WGS84 ↔ a local datum).

2.1 Choosing a transformation

Start from the simplest model that explains the data: every extra parameter must be paid for with more control points and more opportunity to hide a datum error.

TransformationTypical useParametersMinimum control
2D translationShift an arbitrary local gridΔE, ΔN1 point
2D similarity / HelmertLocalisation between two horizontal systemstx, ty, rotation, scale2 points
AffineCAD / scanned-map correction with differential scale or shear6 coefficients3 non-collinear points
3D HelmertDatum / reference-frame transformation3 translations, 3 rotations, scale3 points (use more)
ProjectionGeographic ↔ projected coordinates — the subject of Part 2CRS / projection parametersdefined by CRS
Polynomial / rubber-sheetNon-uniform historical distortionorder-dependentmany points

2.2 The 2D similarity (4-parameter) model

Rotation, uniform scale and two translations — the workhorse of site localisation and the model most survey software calls a "Helmert" in 2D.

E′ = tx + s(E cos θ − N sin θ)
N′ = ty + s(E sin θ + N cos θ)
MOJO 1.x 
from std.math import cos, sin, radians

def similarity(E: Float64, N: Float64,
              tx: Float64, ty: Float64,
              scale: Float64, theta_deg: Float64)
              -> Tuple[Float64, Float64]:
    var t = radians(theta_deg)
    var Ep = tx + scale * (E*cos(t) - N*sin(t))
    var Np = ty + scale * (E*sin(t) + N*cos(t))
    return (Ep, Np)

def main():
    var p = similarity(1000.0, 500.0, 250.0, -100.0, 1.0002, 0.15)
    print(p)

2.3 Estimating a transformation from control points

Replace s·cosθ and s·sinθ with two new unknowns and the non-linear model becomes linear — solvable in one least-squares pass and convertible back to scale and rotation.

With at least two non-identical horizontal control points, a 2D similarity transformation can theoretically be determined. In real work, use more points than the minimum and inspect residuals. Writing a = s·cos θ and b = s·sin θ linearises the model:

E′ = tx + a·E − b·N   /   N′ = ty + b·E + a·N   ⇒   scale = √(a²+b²), θ = atan2(b, a)
MOJO 1.x — least-squares estimation 
from std.math import hypot, atan2, degrees

# 4-parameter similarity from control points via 4x4 normal equations
@fieldwise_init
struct CtrlPt:
    var E:  Float64
    var N:  Float64
    var Ep: Float64
    var Np: Float64

@fieldwise_init
struct Similarity4:
    var tx: Float64
    var ty: Float64
    var scale: Float64
    var theta_deg: Float64

# Solve an augmented 4x5 system M by Gauss elimination (last col = RHS).
# `mut` marks the argument as mutated in place — Mojo arguments are
# immutable by default in 1.0.
def solve4x4(mut M: List[List[Float64]]) -> List[Float64]:
    var n: Int = 4
    # forward elimination
    for k in range(n):
        for i in range(k + 1, n):
            var f = M[i][k] / M[k][k]
            for j in range(k, n + 1):
                M[i][j] = M[i][j] - f * M[k][j]
    # back substitution
    var x = List[Float64]()
    for _ in range(n):
        x.append(0.0)
    for ii in range(n):
        var i = n - 1 - ii
        var s: Float64 = M[i][n]
        for j in range(i + 1, n):
            s = s - M[i][j] * x[j]
        x[i] = s / M[i][i]
    return x

def solve_similarity(pts: List[CtrlPt]) -> Similarity4:
    # Build normal equations for 4 unknowns (augmented 4x5)
    var M = List[List[Float64]]()
    for _ in range(4):
        var row = List[Float64]()
        for _ in range(5):
            row.append(0.0)
        M.append(row)

    for p in pts:
        # E equation: [1, 0, E, -N | Ep]
        # N equation: [0, 1, N,  E | Np]
        # one row per coordinate equation, augmented with the RHS value
        var r1: List[Float64] = [1.0, 0.0, p.E, -p.N, p.Ep]
        var r2: List[Float64] = [0.0, 1.0, p.N,  p.E, p.Np]
        for i in range(4):
            for j in range(4):
                M[i][j] += r1[i]*r1[j] + r2[i]*r2[j]
            M[i][4] += r1[i]*r1[4] + r2[i]*r2[4]

    var x = solve4x4(M)
    # x = [tx, ty, a, b]; recover classical parameters from a, b
    var a = x[2]
    var b = x[3]
    return Similarity4(tx=x[0], ty=x[1],
                       scale=hypot(a, b),
                       theta_deg=degrees(atan2(b, a)))

def main():
    var pts: List[CtrlPt] = [
        CtrlPt(1000.0, 500.0, 1250.10, 399.80),
        CtrlPt(1200.0, 500.0, 1450.02, 400.25),
        CtrlPt(1000.0, 700.0, 1249.70, 600.05),
        CtrlPt(1200.0, 700.0, 1450.12, 600.10)
    ]
    var t = solve_similarity(pts)
    print("tx, ty:", t.tx, t.ty)                       # 249.98 -101.38
    print("scale:", t.scale, "theta_deg:", t.theta_deg)  # 1.00055, 0.05726

2.4 The Helmert 7-parameter model (3D datum transformation)

Three translations, three small rotations and a scale in ppm — the standard way to move a point cloud from one geodetic datum to another, valid only while the rotations stay small.

Xt = Tx + (1 + s) · [ X − Rz·Y + Ry·Z ]
Yt = Ty + (1 + s) · [ Rz·X + Y − Rx·Z ]
Zt = Tz + (1 + s) · [ −Ry·X + Rx·Y + Z ]

where Tx,y,z are translations (m), Rx,y,z are rotations (radians, small-angle form), and s is the scale factor (often given in ppm).

MOJO 1.x — helmert.mojo 
# Helmert 7-parameter in pure Mojo — the small-angle rotation is
# expanded explicitly, so no matrix library is required.
comptime PI: Float64 = 3.14159265358979323846

@fieldwise_init
struct Vec3:
    var x: Float64
    var y: Float64
    var z: Float64

@fieldwise_init
struct HelmertParams:
    var tx: Float64
    var ty: Float64
    var tz: Float64
    var rx: Float64   # radians
    var ry: Float64
    var rz: Float64
    var s_ppm: Float64

def arcsec_to_rad(a: Float64) -> Float64:
    return a / 3600.0 * PI / 180.0

def helmert_forward(p: Vec3, h: HelmertParams) -> Vec3:
    # Small-angle rotation + scale + translation
    var s = 1.0 + h.s_ppm * 1e-6
    var X = p.x
    var Y = p.y
    var Z = p.z

    # small-angle rotation R applied to (X, Y, Z), component by component
    var xr = X - h.rz * Y + h.ry * Z
    var yr = h.rz * X + Y - h.rx * Z
    var zr = -h.ry * X + h.rx * Y + Z

    return Vec3(h.tx + s * xr, h.ty + s * yr, h.tz + s * zr)

def main():
    var h = HelmertParams(
        tx=-117.763, ty=-51.510, tz=139.061,
        rx=arcsec_to_rad(-0.1917),
        ry=arcsec_to_rad(-0.2220),
        rz=arcsec_to_rad(-0.2470),
        s_ppm=-0.191,
    )
    var src = Vec3(-4852421.0, 2560578.0, -3336862.0)
    var dst = helmert_forward(src, h)
    print("Transformed XYZ:", dst.x, dst.y, dst.z)
Do not confuse models. If your data require a datum transformation, projection transformation, geoid correction or time-dependent reference-frame transformation, a simple 2D Helmert fit may merely hide the underlying problem. The rigorous projection step — ellipsoid to Transverse Mercator grid via the Karney-Krüger n-series — is the subject of Part 2 of this course.

3. Site Calibration / Localisation

Brief

Site calibration ties a local survey grid to a global reference system using points observed in both. This chapter sets up the observation equations, solves them by least squares in Mojo, and treats vertical localisation separately. The emphasis is on the residual check: a calibration is only credible if the misclosures at the control points are small, random and independently verified.

A site calibration (or localisation) ties a local total-station or GPS control network to a global coordinate system (e.g. WGS84 / UTM). Given N ≥ 3 common points with coordinates in both systems, we solve for a 2D conformal (4-parameter) or 3D Helmert (7-parameter) transformation by least squares.

Known control

Coordinates in the target grid / CRS.

Observed control

Coordinates measured by GNSS in the working system.

Transformation

Parameters linking the two systems.

Residual check

Differences after applying the transformation.

3.1 Least-squares 4-parameter calibration

Stack the E and N observation equations for every common point, form the normal equations AᵀA and AᵀL by hand, then solve the 4×4 system with Gaussian elimination and partial pivoting — the same pattern reused in the georeferencing and GPS code.

Mojo has no NumPy, so we form the normal equations AᵀA x = AᵀL explicitly and solve the 4×4 system by Gaussian elimination. The four unknowns are the two translations plus the linearised terms a and b; scale and rotation are recovered from a and b in the final step.

MOJO 1.x — calibration.mojo 
from std.math import sqrt, atan2, abs

comptime PI: Float64 = 3.14159265358979323846

@fieldwise_init
struct Point2D:
    var e: Float64
    var n: Float64

@fieldwise_init
struct CalibResult:
    var a: Float64
    var b: Float64
    var tE: Float64
    var tN: Float64
    var scale: Float64
    var rot_deg: Float64

# Solve a 4x4 linear system (normal equations) by Gaussian elimination.
# A is 4x4, L is the right-hand side; returns the solution vector.
def solve4x4(A: List[List[Float64]], L: List[Float64]) -> List[Float64]:
    var n: Int = 4
    # build the augmented matrix [A | L]
    var M = List[List[Float64]]()
    for i in range(n):
        var row = List[Float64]()
        for j in range(n):
            row.append(A[i][j])
        row.append(L[i])
        M.append(row)

    # forward elimination
    for k in range(n):
        # partial pivoting keeps the elimination stable
        var pivot = k
        for i in range(k + 1, n):
            if abs(M[i][k]) > abs(M[pivot][k]):
                pivot = i
        if pivot != k:
            var tmp = M[k]
            M[k] = M[pivot]
            M[pivot] = tmp
        for i in range(k + 1, n):
            var factor = M[i][k] / M[k][k]
            for j in range(k, n + 1):
                M[i][j] = M[i][j] - factor * M[k][j]

    # back substitution
    var x = List[Float64]()
    for _ in range(n):
        x.append(0.0)
    for ii in range(n):
        var i = n - 1 - ii
        var s: Float64 = M[i][n]
        for j in range(i + 1, n):
            s = s - M[i][j] * x[j]
        x[i] = s / M[i][i]
    return x

def calibrate_2d(local_pts: List[Point2D],
                global_pts: List[Point2D]) -> CalibResult:
    var n = len(local_pts)
    var ATA = List[List[Float64]]()
    var ATL = List[Float64]()
    for _ in range(4):
        var row = List[Float64]()
        for _ in range(4):
            row.append(0.0)
        ATA.append(row)
    for _ in range(4):
        ATL.append(0.0)

    for i in range(n):
        var E = local_pts[i].e
        var N = local_pts[i].n
        var r1: List[Float64] = [E, -N, 1.0, 0.0]   # -> global E
        var r2: List[Float64] = [N,  E, 0.0, 1.0]   # -> global N
        var l1 = global_pts[i].e
        var l2 = global_pts[i].n

        # accumulate A^T A and A^T L from the two observation rows
        for p in range(4):
            for q in range(4):
                ATA[p][q] += r1[p]*r1[q] + r2[p]*r2[q]
            ATL[p] += r1[p]*l1 + r2[p]*l2

    var x = solve4x4(ATA, ATL)
    var a = x[0]
    var b = x[1]
    return CalibResult(
        a=a, b=b, tE=x[2], tN=x[3],
        scale=sqrt(a*a + b*b),
        rot_deg=atan2(b, a) * 180.0 / PI
    )

def main():
    var local_pts: List[Point2D] = [
        Point2D(100.000, 200.000),
        Point2D(1250.500, 180.200),
        Point2D(700.300, 1450.800)
    ]
    var global_pts: List[Point2D] = [
        Point2D(540123.456, 6234567.890),
        Point2D(541273.812, 6234542.104),
        Point2D(540719.331, 6235835.021)
    ]
    var r = calibrate_2d(local_pts, global_pts)
    print("a =", r.a, " b =", r.b)
    print("tE =", r.tE, " tN =", r.tN)
    print("Scale =", r.scale, " Rot (deg) =", r.rot_deg)

3.2 Vertical localisation

Treat height separately unless you are deliberately running a rigorous 3D model — a constant offset, then a tilted plane, then a geoid-based correction as the site demands.

Horizontal localisation and height transformation should be treated separately unless a rigorous 3D model is intended. A simple height datum relationship is Htarget = Hsite + ΔH; for more complex work fit a plane, polynomial surface, geoid-based correction or an appropriate vertical datum transformation from control.

MOJO 1.x 
def corrected_height(E: Float64, N: Float64,
                    a: Float64, b: Float64, c: Float64) -> Float64:
    # a + bE + cN: fitted tilt plane applied to a queried position.
    # a, b, c come from the plane fit above (intercept + two gradients).
    return a + b*E + c*N

def main():
    var h = corrected_height(200.0, 300.0, 499.86, 0.0010, 0.0008)
    print(h)
Quality control: never judge a site calibration only by the fitted control points. Reserve one or more independent points and report horizontal and vertical residuals. Watch for outliers, wrong point identification, antenna-height mistakes, multipath and incorrect CRS/datum assumptions.

4. Georeferencing

Brief

Georeferencing gives real-world coordinates to data that has none — raster pixels, scanned plans, DXF drawings and legacy local-grid files. This chapter builds the 6-parameter affine model behind world files, fits it from ground control points in Mojo, and closes with the practical CAD/GIS pipeline and its documentation requirements.

Georeferencing assigns real-world coordinates to raster pixels, CAD drawings, scanned plans, legacy survey files and local-coordinate datasets. The most common model is the 6-parameter affine transform used in world files (.tfw, .jgw, .pgw, …):

Xworld = A · col + B · row + C
Yworld = D · col + E · row + F

where A is pixel width, E is (negative) pixel height, B and D are rotation terms (zero for north-up imagery), and C, F are the world coordinates of the upper-left pixel centre.

4.1 Transformation hierarchy

A ladder of models ordered by how much distortion they can absorb — climb only as far as the source data actually requires.

ModelMinimum controlWhen useful
TranslationOne pointKnown origin offset only
SimilarityTwo points with adequate geometryShift + rotation + uniform scale
AffineThree non-collinear pointsDifferent X/Y scale and shear
Polynomial / rubber-sheetMore control pointsNon-uniform historical distortions

4.2 Affine fit from ground control points

Six unknowns, two equations per GCP: stack them, accumulate a 6×6 normal matrix and a right-hand side, then solve the augmented 6×7 system in place — no linear-algebra library required — and write the coefficients straight out in world-file line order.

MOJO 1.x — georef.mojo 
# 6-parameter affine from GCPs via 6x6 normal equations
@fieldwise_init
struct GCP:
    var col: Float64
    var row: Float64
    var X:   Float64
    var Y:   Float64

@fieldwise_init
struct Affine6:
    var A: Float64   # pixel width
    var B: Float64   # row rotation
    var C: Float64   # X of upper-left centre
    var D: Float64   # col rotation
    var E: Float64   # pixel height (negative)
    var F: Float64   # Y of upper-left centre

# Solve an augmented 6x7 system M by Gauss elimination (last col = RHS).
# `mut` marks the argument as mutated in place — Mojo arguments are
# immutable by default in 1.0.
def solve6x6(mut M: List[List[Float64]]) -> List[Float64]:
    var n: Int = 6
    # forward elimination
    for k in range(n):
        for i in range(k + 1, n):
            var f = M[i][k] / M[k][k]
            for j in range(k, n + 1):
                M[i][j] = M[i][j] - f * M[k][j]
    # back substitution
    var x = List[Float64]()
    for _ in range(n):
        x.append(0.0)
    for ii in range(n):
        var i = n - 1 - ii
        var s: Float64 = M[i][n]
        for j in range(i + 1, n):
            s = s - M[i][j] * x[j]
        x[i] = s / M[i][i]
    return x

def fit_affine(gcps: List[GCP]) -> Affine6:
    # Build normal equations for 6 unknowns (augmented 6x7)
    var M = List[List[Float64]]()
    for _ in range(6):
        var row = List[Float64]()
        for _ in range(7):
            row.append(0.0)
        M.append(row)

    for g in gcps:
        # X equation: [c, r, 1, 0, 0, 0 | X]
        # one row per coordinate equation, augmented with the RHS value
        var r1: List[Float64] = [g.col, g.row, 1.0, 0.0, 0.0, 0.0, g.X]
        # Y equation: [0, 0, 0, c, r, 1 | Y]
        var r2: List[Float64] = [0.0, 0.0, 0.0, g.col, g.row, 1.0, g.Y]
        for p in range(6):
            for q in range(6):
                M[p][q] += r1[p]*r1[q] + r2[p]*r2[q]
            M[p][6] += r1[p]*r1[6] + r2[p]*r2[6]

    var x = solve6x6(M)
    return Affine6(A=x[0], B=x[1], C=x[2], D=x[3], E=x[4], F=x[5])

def main():
    var gcps: List[GCP] = [
        GCP(    0.0,    0.0, 540000.0, 6235000.0),

4.3 Georeferencing a CAD/DXF or GeoPackage — practical pipeline

The office procedure: know the source CRS, choose identifiable control, fit the simplest adequate model, check it on independent points, then transform everything and record what you did.

  1. Identify the source coordinate system and units.
  2. Select clearly identifiable control points.
  3. Measure/obtain their coordinates in the target CRS.
  4. Choose the simplest transformation that adequately models the differences.
  5. Fit the transformation.
  6. Inspect residuals at all control points.
  7. Check independent points.
  8. Transform the complete dataset.
  9. Write CRS metadata and transformation parameters into the project record.

4.4 Point transformation utility

A small reusable routine that applies the fitted similarity parameters to an arbitrary list of points — the last step of any georeferencing job.

from std.math import cos, sin, radians

def transform_points(points: List[Tuple[Float64, Float64]],
                    tx: Float64, ty: Float64,
                    s: Float64, theta_deg: Float64)
                    -> List[Tuple[Float64, Float64]]:
    var result = List[Tuple[Float64, Float64]]()
    var t = radians(theta_deg)

    for p in points:
        var E = p[0]
        var N = p[1]
        var x = tx + s*(E*cos(t) - N*sin(t))
        var y = ty + s*(E*sin(t) + N*cos(t))
        result.append((x, y))

    return result

5. GPS / GNSS Theory in Surveying

Brief

From the pseudorange equation to a working position fix: this chapter covers what a GNSS receiver actually measures, how the non-linear range equations are linearised and solved iteratively for (X, Y, Z, clock bias), how satellite geometry maps into DOP, and why careful survey practice turns a metre-level code solution into a centimetre-level carrier-phase result.

5.1 What GPS/GNSS actually measures

Four observables and data types — code, phase, orbit and a known reference point — are the raw material of every positioning technique from autonomous to RTK.

GPS is one constellation within GNSS. A receiver estimates its position primarily from signals transmitted by satellites whose orbits and clock information are encoded in the navigation message.

Pseudorange

Code-based travel time × c, contaminated by receiver clock error and atmospheric/other errors.

Carrier phase

Very precise phase measurement, but with an unknown integer ambiguity.

Ephemeris

Satellite orbit information used to compute the satellite position at the observation epoch.

Reference station

Known-position station used to estimate common errors for differential or RTK positioning.

5.2 The pseudorange equation

Four unknowns, one equation per satellite: the range model is non-linear, so it is expanded about an approximate position and iterated to convergence.

P = ρ + c(δtreceiver − δtsatellite) + I + T + ε

where ρ is geometric range, c the speed of light, I the ionospheric delay, T the tropospheric delay and ε the remaining effects/noise. With N ≥ 4 satellites we solve the non-linear system for the 4 unknowns (X, Y, Z, c·δt) by linearisation (Taylor expansion) and least-squares iteration: ΔP = H·Δx + ε, where H contains the unit direction vectors from receiver to satellites.

5.3 Iterative least-squares GPS fix

The same Newton-style iteration in dependency-free Mojo: build the Jacobian each epoch, form the 4×4 normal equations, solve, update and test for convergence.

MOJO 1.x — gps.mojo 
from std.math import sqrt

@fieldwise_init
struct Sat:
    var x: Float64
    var y: Float64
    var z: Float64

@fieldwise_init
struct Fix:
    var x: Float64
    var y: Float64
    var z: Float64
    var clock_bias_m: Float64

# Solve 4x4 augmented normal equations by Gauss elimination (in place)
def solve4x4(mut M: List[List[Float64]]) -> List[Float64]:
    var n: Int = 4
    # forward elimination
    for k in range(n):
        for i in range(k + 1, n):
            var f = M[i][k] / M[k][k]
            for j in range(k, n + 1):
                M[i][j] = M[i][j] - f * M[k][j]
    # back substitution
    var x = List[Float64]()
    for _ in range(n):
        x.append(0.0)
    for ii in range(n):
        var i = n - 1 - ii
        var s: Float64 = M[i][n]
        for j in range(i + 1, n):
            s = s - M[i][j] * x[j]
        x[i] = s / M[i][i]
    return x

def gps_fix(sats: List[Sat], pr: List[Float64],
           tol: Float64 = 1e-4, max_iter: Int = 10) -> Fix:
    var n = len(sats)
    var x: Float64 = 0.0
    var y: Float64 = 0.0
    var z: Float64 = 0.0
    var dt: Float64 = 0.0

    for _ in range(max_iter):
        # Geometric ranges & Jacobian rows
        var H = List[List[Float64]]()
        var b = List[Float64]()
        for i in range(n):
            var dx = sats[i].x - x
            var dy = sats[i].y - y
            var dz = sats[i].z - z
            var r  = sqrt(dx*dx + dy*dy + dz*dz)
            var row: List[Float64] = [-dx/r, -dy/r, -dz/r, 1.0]
            H.append(row)
            b.append(pr[i] - (r + dt))

        # Normal equations: H^T H dx = H^T b (augmented 4x5)
        var M = List[List[Float64]]()
        for _ in range(4):
            var mrow = List[Float64]()
            for _ in range(5):
                mrow.append(0.0)
            M.append(mrow)
        for i in range(n):
            for p in range(4):
                for q in range(4):
                    M[p][q] += H[i][p] * H[i][q]
                M[p][4] += H[i][p] * b[i]

        # Newton-style update: linearise, solve, apply correction
        var delta = solve4x4(M)
        x  += delta[0]
        y  += delta[1]
        z  += delta[2]
        dt += delta[3]

        # convergence check on the positional part of the correction
        var step = sqrt(delta[0]*delta[0] + delta[1]*delta[1] + delta[2]*delta[2])
        if step < tol:
            break

    return Fix(x=x, y=y, z=z, clock_bias_m=dt)

def main():
    var sats: List[Sat] = [
        Sat( 1.5e7,  0.0,    2.0e7),
        Sat( 0.0,    1.5e7,  2.0e7),
        Sat(-1.5e7,  0.0,    2.0e7),
        Sat( 0.0,   -1.5e7,  2.0e7)
    ]
    var tx: Float64 = 1000.0
    var ty: Float64 = 2000.0
    var tz: Float64 = 6370000.0
    var true_bias: Float64 = 50.0

    # simulate consistent pseudoranges from the true position
    var pr = List[Float64]()
    for i in range(4):
        var dx = sats[i].x - tx
        var dy = sats[i].y - ty
        var dz = sats[i].z - tz
        pr.append(sqrt(dx*dx + dy*dy + dz*dz) + true_bias)

    var sol = gps_fix(sats, pr)
    print("ECEF fix:", sol.x, sol.y, sol.z, "dt =", sol.clock_bias_m, "m")

5.4 Dilution of Precision (DOP)

One 4×4 inverse summarises the whole sky: Q = (GᵀG)⁻¹ turns unit measurement noise into position noise, and its diagonal and trace give the DOP family.

DOP expresses how satellite geometry amplifies measurement uncertainty. Lower is better; common measures are GDOP, PDOP, HDOP and VDOP:

Q = (HᵀH)−1  ⇒  PDOP = √(Q₁₁+Q₂₂+Q₃₃),   TDOP = √Q₄₄,   GDOP = √tr(Q)
MOJO 1.x — dop.mojo 
from std.math import sqrt, abs

# Invert a 4x4 matrix by Gauss-Jordan elimination with partial pivoting.
# The matrix is extended with the identity to the right; after full
# reduction the right half holds the inverse.
def inv4x4(mut M: List[List[Float64]]) -> List[List[Float64]]:
    var n: Int = 4
    var A = List[List[Float64]]()
    for i in range(n):
        var row = List[Float64]()
        for j in range(n):
            row.append(M[i][j])
        for j in range(n):
            row.append(1.0 if i == j else 0.0)
        A.append(row)

    for col in range(n):
        # partial pivoting: strongest pivot keeps the division stable
        var pivot = col
        for r in range(col + 1, n):
            if abs(A[r][col]) > abs(A[pivot][col]):
                pivot = r
        var tmp = A[col]
        A[col] = A[pivot]
        A[pivot] = tmp

        # normalise the pivot row
        var pval = A[col][col]
        for j in range(col, 2 * n):
            A[col][j] = A[col][j] / pval

        # eliminate this column from every other row
        for r in range(n):
            if r != col:
                var factor = A[r][col]
                for j in range(col, 2 * n):
                    A[r][j] = A[r][j] - factor * A[col][j]

    # extract the right half — the inverse
    var inv = List[List[Float64]]()
    for i in range(n):
        var row = List[Float64]()
        for j in range(n, 2 * n):
            row.append(A[i][j])
        inv.append(row)
    return inv

def main():
    # Unit line-of-sight geometry: each row is a satellite direction
    # vectors, each extended with a receiver-clock column of 1.0.
    var G: List[List[Float64]] = [
        [ 0.7,  0.2, 0.68, 1.0],
        [-0.4,  0.8, 0.45, 1.0],
        [ 0.1, -0.9, 0.42, 1.0],
        [-0.8, -0.2, 0.56, 1.0],
    ]

    # Cofactor matrix Q = (G^T G)^-1, formed explicitly (4x4)
    var GtG = List[List[Float64]]()
    for p in range(4):
        var row = List[Float64]()
        for q in range(4):
            var acc: Float64 = 0.0
            for i in range(4):
                acc += G[i][p] * G[i][q]
            row.append(acc)
        GtG.append(row)

    var Q = inv4x4(GtG)
    var pdop = sqrt(Q[0][0] + Q[1][1] + Q[2][2])
    var tdop = sqrt(Q[3][3])
    var gdop = sqrt(Q[0][0] + Q[1][1] + Q[2][2] + Q[3][3])

    print("PDOP =", pdop)
    print("TDOP =", tdop)
    print("GDOP =", gdop)

5.5 Error sources and why surveying GNSS can be centimetric

Metre-level to centimetre-level: the error budget, and the field and processing practices that shrink it.

High-precision surveying uses carrier-phase observations, differential processing, precise satellite products and carefully controlled field procedures. RTK uses corrections from a reference station or network so that errors common to rover and reference are reduced; double differencing between receivers and satellites eliminates most clock errors.

Error / sourceEffectTypical mitigation
Satellite clock/orbitRange errorBroadcast/precise products, differential methods
IonosphereSignal delayDual frequency (Klobuchar model), differential methods
TroposphereSignal delaySaastamoinen / Hopfield models, differential processing
MultipathBiased observationsGood site selection, antenna design
Receiver noiseMeasurement scatterQuality receiver/antenna, longer observations
Cycle slipsCarrier-phase discontinuityTracking/quality control and reinitialisation
Wrong antenna heightVertical/horizontal errorCareful field measurement and conventions
Wrong CRS/datumSystematic coordinate offsetCorrect CRS metadata and transformation
Key surveying notes:
  • Real GPS applies ionospheric (Klobuchar / dual-frequency) and tropospheric (Saastamoinen, Hopfield) corrections to the pseudoranges before solving.
  • For centimetre-level accuracy, surveyors use carrier-phase observations and resolve integer ambiguities (L1/L2) — the basis of RTK and PPP.
  • Satellite ECEF positions are computed from broadcast ephemerides (Keplerian elements + perturbation corrections) for the time of transmission.

6.1 Residual calculations

The arithmetic of trust: residuals per point, horizontal error per point, RMSE over the whole check set — and the maximum as the single worst-case number you must be able to explain.

vE = Eobserved − Ecomputed
vN = Nobserved − Ncomputed
Horizontal error = √(vE² + vN²)    RMSE = √(Σ eᵢ² / n)
MOJO 1.x 
from std.math import sqrt

def main():
    # Small, dependency-light residual calculation on three check points
    var ve1 = 0.010;  var vn1 = 0.020
    var ve2 = 0.030;  var vn2 = 0.010
    var ve3 = 0.000;  var vn3 = 0.040

    # per-point horizontal error = sqrt(vE^2 + vN^2)
    var e1 = sqrt(ve1*ve1 + vn1*vn1)
    var e2 = sqrt(ve2*ve2 + vn2*vn2)
    var e3 = sqrt(ve3*ve3 + vn3*vn3)

    # RMSE over the check set
    var rmse = sqrt((e1*e1 + e2*e2 + e3*e3) / 3.0)

    print("Errors:", e1, e2, e3)
    print("RMSE:", rmse)
Reporting rule of thumb: state the RMSE, the maximum residual and the point where it occurred. A single large maximum with a small RMSE usually means a gross error (misidentified point, wrong antenna height) rather than a poor transformation — investigate before averaging it away.
