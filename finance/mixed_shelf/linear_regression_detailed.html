1. Introduction to Linear Regression

Before any model can learn, it must first admit what it cannot see — and a line, honestly fitted, is the plainest confession of all.

Linear regression models the relationship between a scalar response y and one or more explanatory variables X by fitting a linear equation to observed data. It is the workhorse of statistical learning — simple, interpretable, and often surprisingly effective. Its appeal is not that it is the most powerful tool in the box, but that it is the most honest: it states plainly how each predictor moves the outcome, and it lets a single number say whether the whole affair was worth the effort.

y = β₀ + β₁ x₁ + β₂ x₂ + … + βₚ xₚ + ε

The goal is to find coefficients β that minimize the sum of squared residuals (ordinary least squares). We implement everything from scratch in Mojo 1.x — a high-performance Python superset designed for AI systems. Learning the mathematics first, then writing each kernel out in full, is how the "two-world" gap between prototyping and production finally closes. Where a step is usually reached for NumPy, the listing drives NumPy through Mojo's interop bridge instead; Chapter 11 and the Chapter 12 table map every step back to its NumPy equivalent.

Key quantities

  • β₀ (intercept / bias): the value of y when every predictor is 0.
  • βⱼ (coefficient / weight): expected change in y for a one-unit increase in xⱼ, holding other predictors constant.
  • ε: unexplained error.
  • ŷ: the prediction produced by the fitted model.
💡 ML interpretation: linear regression is both a statistical model and a supervised-learning algorithm. The training objective is commonly to minimise the sum of squared errors (MSE cost function).

2. Simple Linear Regression

One predictor, one outcome, one line — and yet nearly every idea that matters in statistics hides behind this single straight stroke.

The simplest case: one predictor x and one response y. We fit y = w·x + b using least squares. The Ordinary Least Squares (OLS) solution comes from setting the derivatives of the MSE cost to zero — a moment of calculus that hands us the slope and intercept directly, without iteration:

w = Σ((xᵢ − x̄)(yᵢ − ȳ)) / Σ(xᵢ − x̄)²   ,   b = ȳ − w·x̄

What is being asked here is quietly profound: find the two numbers that make the averaged squared mistakes as small as they can possibly be. Below is a clean class-based Mojo 1.x implementation: explicit typed loops, every weight in plain sight, and systems-level performance and memory safety by construction.

Mojo 1.x — from scratch

Mojo 1.x List — standard prelude 
struct SimpleLinearRegression:
    var w: Float64
    var b: Float64

    def __init__(out self):
        self.w = 0.0
        self.b = 0.0

    def fit(mut self, X: List[Float64], y: List[Float64]):
        var n = len(X)
        var x_mean: Float64 = 0.0
        var y_mean: Float64 = 0.0
        for i in range(n):
            x_mean += X[i]
            y_mean += y[i]
        x_mean /= Float64(n)
        y_mean /= Float64(n)

        var numerator: Float64 = 0.0
        var denominator: Float64 = 0.0
        for i in range(n):
            var dx = X[i] - x_mean
            numerator += dx * (y[i] - y_mean)
            denominator += dx * dx

        self.w = numerator / denominator
        self.b = y_mean - self.w * x_mean

    def predict(self, X: List[Float64]) -> List[Float64]:
        var preds: List[Float64] = []
        for i in range(len(X)):
            preds.append(self.w * X[i] + self.b)
        return preds
⚡ Mojo difference: every Mojo function starts with def, yet type annotations let the compiler generate optimized machine code. var/ref bindings and argument conventions — out self for constructors, mut self for methods that change the struct's state — guarantee memory safety at compile time.

3. Multiple Linear Regression

One predictor is a story; several are a negotiation — each feature must earn its room after the others have spoken.

With p features, the model becomes y = X·β, and the closed-form solution generalizes into a single line of matrix algebra: β = (XᵀX)⁻¹ Xᵀ y. The intercept quietly becomes a column of ones. Each coefficient now answers a harder question — how much does this predictor move the outcome, with every other predictor held still?

Mojo 1.x
from std.python import Python

def main():
    var np = Python.import_module("numpy")

    var X = np.array([[1, 2], [2, 3], [3, 4], [4, 5]])
    var y = np.array([3, 5, 7, 9])

    # add ones column
    var X_b = np.column_stack([np.ones(X.shape[0]), X])

    # closed form: β = (XᵀX)⁻¹ Xᵀ y
    var beta = np.linalg.inv(X_b.T @ X_b) @ X_b.T @ y

    print("β =", beta)  # [1. 0. 2.] → y = 1 + 0·x₁ + 2·x₂

    # numerically stable alternative
    var beta2 = np.linalg.lstsq(X_b, y, rcond=None)[0]
💡 Mojo note: Mojo 1.x's standard prelude centers on List, Dict, and SIMD — it ships no built-in tensor or matrix linear-algebra module. This example therefore drives NumPy through Mojo's Python interop (Python.import_module("numpy")), which is the idiomatic way to use BLAS/LAPACK-grade matrix routines from Mojo. When you write your own raw loops (as in Chapters 2, 4, 6, and 8), you stay in pure Mojo with List and compile-time typed code.
🧠 Note: In practice, avoid explicit inversion for numerical stability — use np.linalg.lstsq (Python) or a QR/SVD-based solver (Mojo). The closed form is instructive but not always the most robust, especially when predictors are correlated.

4. Gradient Descent

When the closed form grows too heavy, the line descends a hill it cannot see the bottom of — and yet, step by careful step, it finds the valley floor.

For large datasets — or many features — inverting a matrix becomes impractical, so we turn to iterative optimization. The cost is the Mean Squared Error, J(β) = (1/2n) Σ (yᵢ − ŷᵢ)², and we walk downhill by nudging each parameter in the opposite direction of the gradient:

w ← w − α·∂J/∂w   ,   b ← b − α·∂J/∂b

Here α is the learning rate — the size of each nudge, small enough to stay on the slope, large enough to actually arrive. For multiple features the matrix form is ∇J = (1/n) Xᵀ(Xβ − y).

Class-based implementation

Mojo 1.x
struct GDLinearRegression:
    var w: Float64
    var b: Float64
    var lr: Float64
    var epochs: Int

    def __init__(out self, lr: Float64 = 0.01, epochs: Int = 1000):
        self.w = 0.0
        self.b = 0.0
        self.lr = lr
        self.epochs = epochs

    def fit(mut self, X: List[Float64], y: List[Float64]):
        var n = Float64(len(X))
        for _ in range(self.epochs):
            var dw: Float64 = 0.0
            var db: Float64 = 0.0
            for i in range(len(X)):
                var pred = self.w * X[i] + self.b
                var error = y[i] - pred
                dw += error * X[i]
                db += error
            dw = -(2.0 / n) * dw
            db = -(2.0 / n) * db
            self.w -= self.lr * dw
            self.b -= self.lr * db
⚡ Mojo performance: Mojo functions with type annotations compile and the loops are aggressively optimized, giving C-like speeds natively without a C extension layer.

5. Regularization

A perfect fit on the data you have is often a lie about the data you don't — so we ask the coefficients to be modest, and the model to think twice.

To prevent overfitting, we add a penalty on the magnitude of the coefficients to the loss. Ridge (L2) shrinks coefficients smoothly toward zero but never quite lets go; Lasso (L1) is more decisive, driving some coefficients to exactly zero and quietly dropping the features that earn their keep least.

Ridge (L2) & Lasso (L1)

Mojo 1.x
from std.python import Python

def main():
    var np = Python.import_module("numpy")

    # synthetic 50×5 data
    var X = np.random.randn(50, 5)
    var y = 2.0 * X[:, 0] - 1.5 * X[:, 1] + 0.5 * np.random.randn(50)

    # Ridge closed form: β = (XᵀX + αI)⁻¹ Xᵀ y
    var alpha = 1.0
    var XtX = X.T @ X
    var XtX_reg = XtX + alpha * np.eye(X.shape[1])
    var beta = np.linalg.inv(XtX_reg) @ X.T @ y
    print("Ridge coeff:", beta)
💡 Mojo note: The Ridge closed form needs a genuine matrix inverse and identity, which Mojo 1.x has no built-in tensor API for — so, as in Chapter 3, the Mojo example delegates the linear algebra to NumPy via Python.import_module("numpy").
📐 Note: Lasso has no convenient closed form — it needs coordinate descent or subgradient methods. Ridge has a convenient closed form as shown.

6. Metrics & Diagnostics

A number that describes every mistake at once is a fine summary — but the residuals, looked at directly, will always tell the truer story.

A model is only as trustworthy as the questions we ask of it. Numbers give us a summary — how large are the errors on average, and how much of the variation did we actually explain? — while the residuals show us where the model went wrong. Both matter, but they answer different questions.

Key metrics to evaluate regression performance:

MetricFormulaInterpretation
SSEΣ (y − ŷ)²Sum of squared residuals
MSE(1/n) Σ (y − ŷ)²Average squared error
RMSE√MSESame units as y
MAE(1/n) Σ |y − ŷ|Robust to outliers
R²1 − Σ(y−ŷ)² / Σ(y−ȳ)²Proportion of variance explained
Mojo 1.x
from std.math import sqrt, abs

def metrics(y_true: List[Float64], y_pred: List[Float64]) -> Dict[String, Float64]:
    var n = len(y_true)
    var sse: Float64 = 0.0
    var mae: Float64 = 0.0
    var sst: Float64 = 0.0
    var mean_y: Float64 = 0.0
    for y in y_true:
        mean_y += y
    mean_y /= Float64(n)

    for i in range(n):
        var e = y_true[i] - y_pred[i]
        sse += e * e
        mae += abs(e)
        sst += (y_true[i] - mean_y) ** 2

    var mse = sse / Float64(n)
    var r2 = 1.0 - sse / sst
    return {"MSE": mse, "RMSE": sqrt(mse), "MAE": mae / Float64(n), "R²": r2}

7. Model Assumptions

The formula is algebra; the assumptions are the fine print. Ignore the fine print and the algebra happily signs its name to a lie.

A least-squares line is always computable, but it is only meaningful when the data roughly respect a few pacts. The statistical validity of linear regression rests on several assumptions:

  • Linearity: the conditional mean is approximately linear in the predictors.
  • Independence: observations/errors are not improperly dependent.
  • Constant variance (homoscedasticity): residual spread is reasonably stable.
  • Normal residuals: mainly important for small-sample classical inference; not required for useful prediction.
  • No severe multicollinearity: highly redundant predictors make individual coefficients unstable.
🧠 Note: For prediction-focused ML, the normality assumption matters less than linearity, independence, and constant variance.

8. Worked Example: Farm Yield Prediction

Five fields, five harvests, one question worth asking: how much water should a farmer pay for — and what will the crop answer back?

Suppose farm yield depends approximately on irrigation water: five fields were measured, each with its own water dose and its own harvest. Real decisions hide behind this simple table. We fit the best-fit line that minimizes squared errors, then use it to predict a yield at a water level nobody irrigated — 225 mm.

Mojo 1.x — from first principles
from std.math import sqrt

def main():
    var x: List[Float64] = [100.0, 150.0, 200.0, 250.0, 300.0]
    var y: List[Float64] = [2.0, 2.8, 3.4, 4.2, 4.9]

    var x_bar = 0.0
    var y_bar = 0.0
    for i in range(len(x)):
        x_bar += x[i]; y_bar += y[i]
    x_bar /= Float64(len(x)); y_bar /= Float64(len(y))

    var num = 0.0
    var den = 0.0
    for i in range(len(x)):
        num += (x[i] - x_bar) * (y[i] - y_bar)
        den += (x[i] - x_bar) ** 2

    var beta1 = num / den
    var beta0 = y_bar - beta1 * x_bar
    var pred = beta0 + beta1 * 225.0

    var sse = 0.0
    for i in range(len(x)):
        var e = y[i] - (beta0 + beta1 * x[i])
        sse += e * e
    var rmse = sqrt(sse / Float64(len(x)))

    print("slope:", beta1, "prediction at 225 mm:", pred, "RMSE:", rmse)

Expected result: the fitted slope is ≈ 0.0146 t/ha per mm, so 225 mm gives a prediction of roughly 3.8 t/ha.

9. Worked Example: Housing Price Prediction

Twenty thousand homes each guessed at a price their owners would accept — and one straight line tries to make sense of them all.

Using the California housing dataset (8 features, ~20,000 samples) we build, train, and evaluate a linear regression model with a full ML pipeline: split, scale, fit, and judge the model only on homes it has never seen. This is the discipline that separates honest forecasting from curve-fitting nostalgia.

Mojo 1.x — full pipeline
from std.python import Python

def main() raises:
    var np = Python.import_module("numpy")
    var datasets = Python.import_module("sklearn.datasets")

    # load — the dataset ships inside scikit-learn, so it arrives over the bridge
    var data = datasets.fetch_california_housing()
    var X = np.array(data.data)
    var y = np.array(data.target)

    # split — every 5th home is held out: test_size = 0.2, and no seed to forget
    var hold = np.arange(0, len(y), 5)
    var X_test = X[hold]
    var y_test = y[hold]
    var X_train = np.delete(X, hold, axis=0)
    var y_train = np.delete(y, hold)

    # scale — z-scored with TRAIN statistics only, never the test set's
    var mu = X_train.mean(axis=0)
    var sigma = X_train.std(axis=0)
    var X_train_s = (X_train - mu) / sigma
    var X_test_s = (X_test - mu) / sigma

    # train — the 8×8 normal equations go through NumPy, as in Chapter 3
    var beta = np.linalg.solve(X_train_s.T @ X_train_s, X_train_s.T @ y_train)

    # predict & evaluate — only on homes the model has never seen
    var y_pred = X_test_s @ beta
    var mse = np.mean((y_test - y_pred) ** 2)
    var r2 = 1.0 - np.sum((y_test - y_pred) ** 2) / np.sum((y_test - y_test.mean()) ** 2)

    print("Test MSE:", mse)
    print("Test R²: ", r2)
    print("Top 3 coefficients:", beta[:3])
💡 Mojo note: Two stages cross the bridge: the dataset itself (it ships inside scikit-learn) and the 8×8 solve, because Mojo 1.x still ships no built-in matrix API — the same trade-off as Chapter 3. The split, the scaling, and the scoring are the pipeline you just read.
📊 Output: For California housing, expect MSE ≈ 0.55 and R² ≈ 0.58. Feature scaling matters when predictors have very different units.

10. Worked Example: Sales Forecasting

Every dollar of advertising makes a promise to the sales figure; the model's job is to read those promises honestly.

Predict monthly sales using advertising spend on TV, radio, and newspaper across 200 synthetic observations. The data were made with a known truth — spend does drive sales, but each channel drives it differently — and then noise was added to make the truth harder to see. That is always the deal: a model that recovers the signal beneath the noise has actually learned something.

Mojo 1.x
from std.python import Python

def main():
    var np = Python.import_module("numpy")
    np.random.seed(42)
    var n = 200

    var TV = np.random.uniform(0, 300, n)
    var radio = np.random.uniform(0, 80, n)
    var newspaper = np.random.uniform(0, 60, n)
    var sales = 5.0 + 0.045 * TV + 0.18 * radio + 0.01 * newspaper + 2.0 * np.random.randn(n)

    var X = np.column_stack([TV, radio, newspaper])
    var y = sales

    # closed form: β = (XᵀX)⁻¹ Xᵀ y
    var beta = np.linalg.inv(X.T @ X) @ X.T @ y
    var y_pred = X @ beta
    var mae = np.mean(np.abs(y - y_pred))

    print("Coeffs:", beta)
    print("MAE:", mae)
💡 Mojo note: The fit here uses the closed form β = (XᵀX)⁻¹Xᵀy through NumPy via Python interop, matching the Chapter 3 pattern — pure-Mojo loops for this would require implementing the matrix solve by hand.
📈 Interpretation: Radio has the highest coefficient (~0.18), suggesting it is the most effective channel per unit spend in this synthetic dataset.

11. Why Mojo 1.x? Python vs Mojo

Python writes the thought, and C pays the bill for it. Mojo is an attempt to have both the thought and the speed in one language.

Python is the undisputed king of AI prototyping, but it suffers from the "two-world problem" — easy to write yet slow to execute, requiring C/C++ extensions (like NumPy) for performance. The prototype is born in one world and must be rebuilt in another before it can run fast. Mojo 1.x bridges this gap.

  • Familiar Syntax: It reads like Python, accessible to data scientists.
  • Systems-Level Performance: Even though functions are written with def, Mojo's type annotations and strict static typing compile to optimized machine code via LLVM.
  • Memory Safety: var/ref bindings and argument conventions (mut self, out self) catch data races and memory leaks at compile time.
  • Hardware Utilization: Scales from CPUs to GPUs and custom AI accelerators without changing the core algorithmic code.

In Python, linear regression relies on NumPy (written in C) for speed. In Mojo, you write the raw loops yourself and achieve C-like speeds natively while keeping Python's expressiveness.

💡 Strategy: Learn the mathematics first, then implement the kernels yourself — the left column of the Chapter 12 table is what you would write in Python, the right column is what compiles. Use Python's mature ecosystem (scikit-learn, pandas) for production ML, and Mojo where you need compiled high-performance kernels.
