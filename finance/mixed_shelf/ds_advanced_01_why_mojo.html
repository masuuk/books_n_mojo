Part I: Foundations

🔥 Why Mojo for DS/ML?

Mojo vs Python — understanding where Mojo fits in the data science ecosystem.

If you profile a real machine learning pipeline, an uncomfortable pattern shows up almost every time: the Python you wrote spends most of its life waiting on someone else's compiled code. pandas is fast because it's C underneath. PyTorch is fast because it's CUDA and C++ underneath. Your own glue code — the feature engineering, the custom loss function — is usually the slow part.

Mojo is a new programming language designed to bridge the gap between high-level productivity (like Python) and low-level systems performance (like C++). It's built on MLIR and offers first-class support for GPUs and TPUs.

The Two-Language Problem

Every mature numerical Python library is secretly two libraries. The research code is in Python, the hot path is in C++/CUDA, and the seam between them is maintained by hand. Mojo collapses that table into one row: a single language that's Python-shaped enough for research, but compiled enough for production.

LayerRoleLanguage
ResearchData loading, experimentationPython
Hot pathTensor ops, kernelsC++ / CUDA
MojoBoth, in one languageMojo

Mojo vs Python

  • Python: Rapid prototyping, rich ecosystem, but slow for compute-heavy tasks.
  • Mojo: Python-like syntax, compiled performance, GPU-native, gradually typed.

Getting Mojo onto Your Machine

Mojo 1.x runs on Mac, Linux, or Windows with WSL. You can install it with any Python or Conda package manager, but the two recommended routes are uv and pixi:

uv
pixi
# Install uv if needed
curl -LsSf https://astral.sh/uv/install.sh | sh

# Install Mojo…
uv pip install mojo

# …or create a project and add it
uv init temperature-analyzer
cd temperature-analyzer
uv add mojo
# Install pixi if needed
curl -fsSL https://pixi.sh/install.sh | sh

# Create a project with the Modular channel
pixi init temperature-analyzer   -c https://conda.modular.com/max/   -c conda-forge
cd temperature-analyzer
pixi add mojo
pixi shell

Create analyzer.mojo in your favorite editor, add a main() function — the entry point every Mojo executable uses — and run it with mojo analyzer.mojo. If you see the output, your setup works:

Mojo
terminal
def main():
    print("Temperature Analyzer")
$ mojo analyzer.mojo

A First Look: The Same Algorithm in Mojo

Mean Squared Error, written in Mojo 1.x:

Mojo 1.x
# Compute Mean Squared Error
from tensor import Tensor, Float32

def mse(a: Tensor[Float32], b: Tensor[Float32]) -> Float32:
    assert a.shape == b.shape
    var diff = a - b
    var squared = diff ** 2.0
    return squared.sum() / Float32(a.size)

The three-line NumPy form (np.mean((a - b) ** 2)) reaches the same answer, but it dispatches into C and the surrounding function carries no compile-time types. Here the shapes, dtypes and reduction are all checked before the program runs.

Python Interop from Day One

You don't give up the Python ecosystem when you write Mojo. The standard library's std.python module brings PythonObject and import_module, so NumPy, pandas, and friends slot straight into a Mojo program:

Mojo
from std.python import Python

# Mojo has no std.python.numpy, so build the Python-side list by hand.
def to_python_list(data: List[Float64]) raises:
    var out = Python.list()
    for v in data:
        out.append(v)
    return out

var np = Python.import_module("numpy")
var pytemps = np.array(to_python_list(temps))
var std_dev = np.std(pytemps)
print("Temperature standard deviation:", std_dev)

This is the pragmatic Mojo workflow for data science: keep the Python libraries you already trust for I/O and statistics, and drop into Mojo where the loops get hot. The quickstart's full temperature analyzer walks exactly this path — a List[Float64] of readings, a calculate_average() function marked raises to reject empty data, a try/except boundary in main(), and a NumPy standard deviation at the end.

The 1.0 Milestone

Mojo 1.x shipped with source stability in 2026, and the compiler, standard library, and toolchain are open source under Apache 2.0 (with LLVM exceptions) in the modular/modular GitHub repository. For a data scientist, that matters more than a version number: the language you're betting a pipeline on is now inspectable, forkable, and community-driven.

The 1.0 release also settled the syntax this series teaches: def for every function, var mandatory for local bindings, mut for mutable arguments, comptime for compile-time constants, and t-strings (t"...{expr}...") that give you interpolation without f-string allocation churn.
